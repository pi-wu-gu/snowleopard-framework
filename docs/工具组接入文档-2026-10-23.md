## 一、接入方式

```java
// 宿主（shell 已内置，第三方模组可直接调）
Result r = EntityToolsRuntime.dispatch(modelId, group, tool, params);
```

- **`modelId` 由调用上下文注入（红线 6：不可作为工具参数伪造）**——每个模型一份模块（绑定/状态/监视流互不越界）；
- 权限预检在 dispatch 入口（核心权限表 `mod:snowleopard:<group>`）；权限文件可逐工具关掉；
- 全部结果走核心 `Result` 四级（Ok/Warn/Severe/Error），**失败必 Error 带原因，不静默不假成功**；
- 未开启感官（sense=OFF）时控制类工具显式拒绝——禁用必须显式（假成功比失败更坏）。

### craft（合成，2026-10-24 03:55 (UTC+8) 接入）—— 组 `mod:snowleopard:craft`

| 工具 | 语义 | 关键口径 |
|---|---|---|
| `craft_recipes(keyword?, limit=20)` | 列可用工作台配方（id/输出/材料清单/数量） | 只读；keyword 过滤 id 与输出名 |
| `craft(recipe_id, count=1)` | **配方直合成**：从 `self:pack` 扣料 → 产物（含桶/碗余料退回）回背包 | count 1..8；材料不足 → **Error 列缺口清单**；背包放不下 → **Error 并全量退料**（物品不消失）；产物结果与槽位核实后返回 |

裁决落地：**不要求工作台邻接**（3×3 直合成）；网格合成不做（对 LLM 是三个状态问题换"操作像人"）；
材料事务性 = 先校验后统一扣、失败回滚（`addToContainer` 失败即退料）。产物如实按配方数量返回（原木→4 木板）。

### avatar（载体，2026-10-24 01:30 (UTC+8) 接入）—— 组 `mod:snowleopard:avatar`

| 工具 | 语义 | 关键口径 |
|---|---|---|
| `avatar_bind()` | 把 `entity.pick` 绑定的实体登记为我的**主载体** | 实体必须是 `snowleopard:avatar`（`/summon snowleopard:avatar` 生成）；重名 → 拒绝（裁决 4）；重复绑定 = 主载体换人（旧主降级保留） |
| `avatar_unbind()` | 解除我全部载体与定时 | |
| `avatar_schedule(interval_sec)` | 定时唤醒间隔（**真实时间**，下限 60 秒） | 实体未加载 → **跳过并记原因，绝不补发**（裁决 3）；nextFireAt 永远前进 |
| `avatar_status()` | 载体与排程 | 含 `loaded`（实体是否在加载区） |

**三类唤醒源**（都是事件，不是工具）：① 玩家**右键/被打**主载体（10 秒冷却；被打可由 `config/snowleopard-wake.json` 的 `on_damage` 关闭）；② **定时**到点（真实时间）；③ 聊天**点名实体名称**（编号只提示，M12 通道）。
外部触发的 `from` 是**伪 ID**（`ext-clock` / `ext-player-<名>` / `ext-mention-<名>`）——核心 `Ids.Caller` 不允许冒号，且绝不借用真实模型 ID（否则自唤起/黑名单判定失真）。唤醒失败（在运行/配额满/被拉黑）→ **自动补一条提示**。
载体外观复用豹猫（`OcelotModel` + 原版贴图，零新资源），**不继承 `Ocelot`**（驯服/繁殖/猎鸡/喂鱼刷猫都不存在）；`MISC` 类别、不自然生成、`removeWhenFarAway=false`。

### chat（聊天，2026-10-24 01:00 (UTC+8) 接入）—— 组 `mod:snowleopard:chat`

| 工具 | 语义 | 关键口径 |
|---|---|---|
| `chat_send(text)` | 以**载体身份**发言（前缀 `[雪豹·<名称>]`，无名称用编号） | 单条 ≤256 字符；**最小间隔 0.5s 可配**（`config/snowleopard-chat.json` 的 `min_interval_ms`，0=不限）+ 每分钟 30 条（`max_per_minute`，0=关）；超限**报错并给剩余等待**，不静默丢；无在线玩家 → Error（不假送达） |
| `chat_read(limit=20)` | 显式读未读全文，**读取即推进游标** | 只含玩家来源（模型互写不进这里，防回声）；想看模型说过的话用 `chat_search` |
| `chat_search(...)` | 按天 + 关键词（空格分词 AND，大小写不敏感）+ 时间窗 + 来源过滤 | 必回 `matched / scanned / truncated` 三个数——只回 matched 会把"没搜到"和"没搜完"混成一件事 |
| `chat_status()` | 游标自检 | `lastReadSeq`（注入/已读）与 `lastScanSeq`（提及）是**两个游标** |

**注入与提示是三条独立通道**，别混：
① **注入块**：`pull()` 取未注入的**玩家来源**消息（`⟦雪豹·聊天⟧…⟧`，换行已折叠、`⟦⟧` 已剥离、单条 ≤200 字、整块 ≤20 条/2000 字），`pull` **不推进**游标——接入方 `ack(seq)` 才算注入完成（重复可见优于静默丢失）；
② **轮末摘要**：`turnLine` 追加 `· 新聊天 N 条`（每轮报，直到 ack）`· 被提及 M 次`（只报一次，consume 即清）；
③ **唤醒**：提到**实体名称**才可能触发（M13），**编号只提示**。

存储：`shared/chat/<yyyy-MM-dd>.jsonl`（append-only，seq 全局单调跨天不重置）+ 每模型 `ids/<模型>/chat-cursor.json`。
保留 30 天（`retention_days`），启动时清一次。配置文件不存在 = 全默认。

### 内置四组（`builtin:core:*`，2026-10-23 20:10 (UTC+8) 接入）

实体组之外，核心自带的四组**也走同一个壳侧入口**（`EntityToolsRuntime.dispatch` 最早期分流到
`BuiltinRuntime` → 核心 `BuiltinToolkit`）。清单由核心 `bootstrap` 注册，**壳不复制 schema**。

| 组全名 | 可用性 | 工具 | 产物落点 |
|---|---|---|---|
| `builtin:core:session` | ALWAYS_ON | `session_yield` · `session_usage` | 内存（会话态） |
| `builtin:core:memory` | ALWAYS_ON | `memory_read` · `memory_default` · `memory_correct` · `memory_repair` | `snowleopard/ids/<模型>/memory*/` |
| `builtin:core:todo` | NORMAL | `todo_add` · `todo_add_sub` · `todo_mark` · `todo_list` · `todo_delete` · `todo_purge` | `snowleopard/ids/<模型>/todo/todo.json` |
| `builtin:core:notes` | NORMAL | `note_mkdir` · `note_create` · `note_append` · `note_read` · `note_search` · `note_delete` | `snowleopard/ids/<模型>/notes/`（删除进 `.trash/<时间戳>/`） |

接入要点（改壳前先看）：

1. **分流必须在实体组权限判定之前**——实体组按 `mod:snowleopard:<group>` 判权限，
   内置组若走那条会把 `builtin:core:*` 一律判成"无此组"而拒掉；
2. 内置组权限组名是 `builtin:core:<group>`，**不因自带而免检**；
3. `BuiltinRuntime` 缓存的是**句柄**（模型编号 → 它的家）不是能力对象——`forget(model)` 只是丢句柄，
   盘上数据重建即恢复（存储类是文件视图）；
4. 跨 ID 隔离照旧：B 的 `todo_list` 看不到 A 的条目，B 的 `note_read` 读不到 A 的文件（真机 M9 已验，含盘上路径）；
5. 两段式（`note_delete` / `memory_correct`）在壳侧行为一致：首段只给 `confirm_token` 不落盘。

## 三、红线（违反即拒绝，带原因）

| # | 红线 | 落点 |
|---|---|---|
| 1 | **其他编号（模型）的实体一律无法使用**（含观察性操控） | `interact.attack` 等实体目标操作的 exclude 预检 |
| 2 | **caller/model 编号不可伪造** | dispatch 入口显式收取，不走工具参数 |
| 3 | **假成功比失败更坏** | 完成判定全走服务端回推；失败 Error 带原因；禁用显式拒绝 |
| 4 | **未开启感官=控制类工具禁用** | sense=OFF 时 move/view/interact/item 实体目标/watch 实体目标拒绝 |
| 5 | **仅已加载区块**（未加载返空气不报错——必须声明） | `world.query` 的 note 字段 |
| 6 | **感知面与使用面分层** | watch 查询/world 查询可见他人实体但标 `controller` 归属；使用（操控）才过红线 1 |

## 四、危险动作权限矩阵与审批链

### 权限矩阵（`reversible/state` → 核心权限表）

| 工具 | reversible | state | 审批 |
|---|---|---|---|
| `interact.attack` | **false** | changes_world | **玩家目标两段式**（见下）；非玩家直通 |
| `interact.use` | depends | changes_world | 权限表 |
| `interact.place` | **false** | changes_world | 权限表 |
| `interact.break` | **false** | changes_world | 权限表 |
| `move.move` / `move.goto` | true | changes_world | 权限表 |
| `item.move_item` | true | changes_world | 权限表 |
| `item.drop` | **false** | changes_world | 权限表 |

- 矩阵由 `ToolSchemasMatrixTest` 逐工具锁定（改标注=改政策，测试即政策快照）；
- 逐工具关闭走权限文件（`Permissions.fromFiles`）：`mod:snowleopard:<group>` + 工具名。

### 攻击玩家目标：两段式审批（confirm_token）

```
首段：interact.attack(target=<玩家>) 
      → Warn {pending, confirm_token, preview, target}   ← 不执行任何攻击
二段：interact.attack(target=<玩家>, confirm_token=<token>)
      → 核销通过才执行；结果=Ok(血量回推) 或 Error
```

- 令牌语义（核心 `ConfirmGate`）：**单次使用**、TTL 10 分钟、**digest 绑定目标+当前血量**——
  两段之间目标被换/血量变了令牌即失效（防"看的是 A、打的是 B"）；
- 令牌是**发给模型自身的确认**（非外部审批方）——攻击真人默认走此链；
- 非玩家目标（怪物等）不走审批，直接执行（血量回推判定）。

## 五、数值与单位口径（全工具统一）

| 量 | 单位 |
|---|---|
| 时间 | tick（20 tick=1 秒）；`duration_ticks`/`max_ticks` 以 tick 计 |
| 角度 | 度；yaw 0=+z 南，-90=+x 东；pitch 负=抬头 |
| 坐标 | 绝对坐标 `"x,y,z"`；box=`"x1,y1,z1,x2,y2,z2"` |
| 方向 | `forward|back|left|right`（相对开始时朝向冻结，非实时朝向） |

## 六、常见失败原因速查

| 现象 | 原因（Result.Error 文案） |
|---|---|
| 控制类工具全拒 | 感官未开启/未绑定（或绑定实体已死亡） |
| attack/place 目标拒 | 红线：其他编号模型的实体 |
| attack 玩家目标不执行 | 首段签发中——需带 confirm_token 二次调用 |
| goto 拒 | 不可达预检：高差>3 / 流体 / 未加载区块 |
| break 超时 | 硬方块需求时长超预算（黑曜石 250 tick 等） |
| world.query 结果不全 | 仅已加载区块 + 超量截断（truncated=true） |
| watch_events 空 | 该期无记录（稀疏是常态）或未监视该实体 |
