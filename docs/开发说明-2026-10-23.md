## 一、定位与架构边界（双件套）

```
┌────────────────────────────────────────────┐
│ 雪豹框架（本仓，NeoForge mod，薄壳）             │
│  ① 装配门面 SnowLeopard.bootstrap(...)        │
│  ② SPI 发现 loadDiscovered(MOD, modClassLoader)│  ← 类加载器交接点
│  ③ 启动报告 → 日志                             │
│  ❌ 业务逻辑/决策/记忆算法——一律不进壳            │
├────────────────────────────────────────────┤
│ snowleopard-core（雪豹决策核心，零 MC，jarJar）  │
│  工具组注册/门禁/ID 隔离/记忆/会话/确认/四级结果    │
└────────────────────────────────────────────┘
```

- **壳里出现决策代码 = 架构漂移**。壳的职责穷举于上面三件事——
  **但 2026-10-24 起多了第 ④ 件：AI 执行端 `io.github.piwugu.snowleopard.host`**
  （用户裁决：独立 = 不跨仓耦合，**本项目要有完整 AI 系统**，执行端就建在本仓内，
  见 `docs/AI执行端设计-2026-10-24.md`）。这不是"决策代码进壳"，而是"壳里本来就该有那个会做决定的人"：
  它仍然不绕过权限、不自己存契约，只是把 `pending()` 变成真的会话。
  壳里**不许**有的是：复制 core 的清单、自己实现记忆/权限/四级结果。
- 双端加载（BOTH）：无界面、不依赖资源包/渲染/语言——构造期装配安全（与 friday 客户端宿主不同）。
- 其他模组接入方式：实现 `snowleopard.core.spi.ToolGroupProvider`（SPI 自动发现，
  `coreApi` 不匹配拒载、限定名由装载器拼、来源强制标注），或经 `SnowLeopardMod.core()` 取门面。

## 二、装配路径（壳的全部逻辑）

1. 存储根：`<gameDir>/snowleopard/`（ID 家的父目录）；
2. 权限政策**显式二选一**（S3）：`config/snowleopard-permissions.json` 存在 → `Options.fromFiles`；
   不存在 → `Options.allowAll()` + **WARN 点名**（不静默继承）；
3. `SnowLeopard.bootstrap(storage, opts)`；
4. `loadDiscovered(Names.SourceType.MOD, getClass().getClassLoader())`——NeoForge 的
   ModClassLoader 可见全部模组类，外部 provider 由此注册；单模组自测用 `Names.SourceType.LOCAL`；
5. `startupReport()` 逐行入日志（来源分布/消歧表/WARN 汇总/门面默认值）；
6. `SnowLeopardMod.core()` 静态门面给其他模组（装配失败返回 null，调用方判空）。

## 三、版本链

| 件 | 版本 | 来源 |
|---|---|---|
| MC | 1.21.1（Java 21 线） | 模板 testmod-template-1.21.1 |
| NeoForge | 21.1.259 | 同上 |
| snowleopard-core | **0.7.1**（本仓 `gradle.properties` 的 `snowleopard_core_version`，改核心必须两处同步） | 核心仓 `./build.sh publish ../../project/snowleopard-framework/libs/m2` |

- 核心升级：核心仓改 VERSION → `build.sh publish` → 本仓 `gradle.properties` 的
  `snowleopard_core_version` → `./gradlew build` → 断言 jarjar 内嵌核心与 m2 一致；
- jarJar 用**精确版本**（区间要拉版本清单，离线即失败；兼容性由 coreApi 校验兜底）。
