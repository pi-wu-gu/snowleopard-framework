# AI 执行端设计（完整 AI 系统，本项目内）

> 2026-10-24 02:25 (UTC+8)。**前提纠正（用户裁决）**："本项目独立"指**不与其他仓库耦合与同构**
> （不接星期五），**不是没有 AI**——本项目需要**完整的 AI 系统**：唤醒 → LLM 会话 → 工具执行 → 回写的
> 全链路都建在本仓库内。此前文档里所有"执行端 = 接入方（本项目外的 LLM 宿主）"一律读作
> **"执行端 = 本项目的 host 层"**；"壳绝不假装执行"的约束不变——host 层是真的执行，不是假装。

## 一、职责总账：三层各管什么

| 层 | 管什么 | 不管什么 |
|---|---|---|
| **core**（零依赖） | 唤醒登记/裁决、权限表、内置四组能力（会话预算/记忆/任务/笔记）、群组、`Compressor` 契约 | 不发 HTTP、不存对话历史、没有主循环 |
| **shell + entitytools**（MC 侧） | 工具执行面（实体 11 组 + 内置 6 组 + chat/avatar 单一 dispatch 入口）、事件（聊天/互动/定时）、聊天栏 | 不认识 LLM 协议 |
| **host（新建，本设计）** | **LLM 客户端、对话历史、工具循环、唤醒轮询、会话生命周期** | 不绕过权限（dispatch 时 caller_id 照常 core 注入） |

关键点：**host 是"真的执行"**——它把 `pending()` 的请求变成真正的 LLM 会话，工具真的被调用、
聊天真的发出去、`complete()` 真的回写。此前"壳无 LLM 驱动、`rejectUnrunnable` 明确 failed"的设计
针对的是"壳不假装"；host 层出现后，执行是真的，约束自然满足。

## 二、架构决策（本设计定死，除非用户否决）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **host 在框架仓内、与 MC 服务器同 JVM**（`io.github.piwugu.snowleopard.host` 包） | 工具执行全在进程内（`EntityToolsRuntime.dispatch` 单一入口）；跨进程要 RPC 桥，现阶段纯属自找复杂度 |
| 2 | **LLM 协议 = OpenAI 兼容 `/chat/completions`** | 一套客户端通吃主流提供商（DeepSeek/GLM/Moonshot/OpenAI/本地 ollama 等）；HTTP 用 Java 21 内置 `HttpClient`，JSON 用 core 的 `Json`——框架不新增第三方依赖 |
| 3 | **配置 = `config/snowleopard-llm.json`**（gameDir 下，**永不入库**） | `base_url` / `api_key` / `model` 必填；可选 `models`（按模型 ID 覆盖模型名）、`temperature`、`max_rounds`（轮次预算，默认 12）、`history_window`（带入历史的消息条数，默认 40） |
| 4 | **对话历史 = `ids/<模型>/host/rounds.jsonl` append-only** | 每轮一行（唤醒原因 / 助手最终文本 / 工具调用摘要 / 消耗）；**不带全量消息数组**（历史窗口由 host 现场装配，落盘只留可追溯的轮记） |
| 5 | **触发 = 只由唤醒驱动**（`pending()` 轮询，每 20 tick 一次） | 会话=响应"有人/时钟/点名叫我"；无请求不开会话（空闲空转纯属烧钱）。多个 pending → host 层 FIFO 顺序开会话（**执行端自己的队列，可见且诚实**——与"core 不排队"不冲突：core 只是不隐式排队） |
| 6 | **会话互斥 = 复用 `RuntimeView`**（`WakeBridge.beginSession/endSession`） | 锁文件 + 进程内表双保险已建好；同一模型并发开会话是错误，不是排队 |
| 7 | **工具循环**：带全量清单（注册表里该模型可见的组）→ 逐个 `dispatch` → 结果回填 → 直到无工具调用 / `session_yield` / 轮次预算耗尽 | 权限照旧在 dispatch 内由 core 表裁决（caller_id 不可伪造）——**host 不给模型开任何后门** |
| 8 | **轮末收尾**：`chat ack`（注入过的才推进游标）→ `consumeTurnLine` → `complete(reqId, …)` → 轮记落盘 | 沿用"推成功才记账"：上下文真被模型看到了才 ack |
| 9 | **`Compressor` 落地**：host 启动时 `Options.withCompressor(llm::compress)` 注入 | 记忆自动吸收从"等宿主"变"真的能跑"——这是完整 AI 系统的直接收益 |
| 10 | **轮次间的提醒注入**：唤醒 prompt + `turnLine` 摘要行 + `chat pull` 块 | 与 M12 的注入块同一来源，host 只是"把它塞进上下文"的那个角色 |

## 三、会话一轮的形状

```
[poll] ext-player-SnowTester → clienttest（"玩家右键了你…"）
[beginSession clienttest]
[装配] system（身份/能力/世界常量） + 历史（rounds 窗口）
      + user（唤醒原因 + ⟦雪豹·聊天⟧块 + 提醒行）
[LLM] → tool_call: chat_send("你好，我看到你右键我了")
      → tool_call: sense.open / entity.pick …
[dispatch] 逐个执行，结果回填
[LLM] → 无工具调用，最终文本 → 轮记
[收尾] ack(chat) · consumeTurnLine · complete(reqId, ok) · endSession
```

## 四、风险表

| # | 风险 | 防线 |
|---|---|---|
| 1 | **API key 泄漏**（仓库公开！） | key 只放 `run-server/config/`（已 gitignore 的目录）；**提交前 grep 自检**；文档里只写键名不写值 |
| 2 | 模型刷工具/死循环 | `max_rounds` 预算（默认 12）+ `session_yield` + 工具侧既有冷却/配额（唤醒 20/h、聊天 0.5s、群组上限） |
| 3 | 多模型同时被唤 → 串行会话延迟 | v1 单线程 FIFO（正确性优先）；并发是 host 内线程池的事，v2 再说，**先记账** |
| 4 | LLM 输出伪造工具结果 | 工具结果只来自 dispatch 返回值，模型文本里的"结果"不进任何存储——假成功家族的老防线 |
| 5 | 历史无限膨胀 | `history_window` 只带最近 N 条；轮记 append-only 但每行很小；压缩交给 `Compressor`（决策 9） |
| 6 | 唤醒风暴（定时 + 玩家 + 点名同时到） | host FIFO + 会话互斥；同模型多请求合并进同一会话的 user 段（v1 简化为逐个开会话，先记账） |
| 7 | 提供商接口差异 | 只承诺 OpenAI 兼容；不兼容的提供商 = 用户换兼容端点（各家基本都有） |
