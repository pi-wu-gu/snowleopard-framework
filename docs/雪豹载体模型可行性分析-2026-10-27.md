## 四、两个待裁决点

### 1. 碰撞箱 vs 模型缩放（必须选一个）

当前 `EntityType.sized(0.6f, 0.7f)` 是按豹猫体型定的，模型是 **0.79 × 1.44 格**，两者不匹配。

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A（推荐）** | `sized(0.9f, 1.4f)` | 视觉与碰撞一致；右键射线更易命中；雪豹本就是大型猫科 | 1.44 格高，1 格高的洞钻不过（原版豹猫能） |
| B | 模型 `scale(0.55)` | 保持小巧灵活，走位接近豹猫 | 视觉像幼崽；碰撞箱仍要小幅上调到约 0.6×0.85 |

建议 A。载体由 AI 驱动、走的是寻路 + 直设速度，碰撞箱变大不改变行为，只影响"能钻多小的缝"。

### 2. 尾巴长度（可接受，但需知情）

尾巴 2.2 格、伸出身后约 3 格，总长 4.68 格。会穿墙、穿门、穿过方块（原版狼/狐狸同理，是 MC 通病）。
三种处理，按需选：

- **保持原样**（推荐先这样，视觉上雪豹的尾巴本来就是标志）；
- 缩短 `tail_4..7` 的 z 跨度（改 bbmodel 后重跑 `bbmodel_to_java.py`）；
- 在 `setupAnim` 里给 `tail1.xRot` 一个更明显的下弯基线，让尾巴垂向地面而不是水平后伸。

## 五、风险与限制

1. **步态驱动方式需要真机确认**：`setupAnim` 用的是 `limbSwing / limbSwingAmount`。载体的移动是直设
   `deltaMovement`（不经原版 goal），`LivingEntity.aiStep` 按实际位移累加 `walkAnimation`，理论上有效；
   但**必须真机看一眼走动时腿是否真的摆**，这是唯一"未经验证"的假设。
2. **alpha test 硬切**：74% 透明的毛发片在 cutout 下边缘是锯齿状（阈值 0.1），符合原版风格，不做半透明排序。
3. **无 baby 变体**：载体不繁殖，无影响。
4. **多载体性能**：42 cube × 若干载体，每帧开销可忽略（原版铁傀儡 30+ cube）。
5. **无原版 AI 约定不受影响**：只换模型与渲染器，`AvatarEntity` 仍然无 goal、无自然生成。

## 六、建议执行路径

1. 按 §三 六项改名适配（40 分钟），碰撞箱取方案 A；
2. `gradlew build` + 复制 jar，真机跑既有 22 条断言（确保没碰坏载体/拾取/抓取链路）；
3. 肉眼验收清单：**朝向**（头朝行进方向）、**贴地**（脚不悬空不陷地）、**大小**（与玩家/豹猫对比）、

4. 尾巴/尺寸不满意的再走 §四 微调。

## 七、不改的东西（避免过度设计）

- 不加 GeckoLib 等第三方动画库（本仓惯例是零额外依赖、自写 renderer）；

## 十五、眼皮到底能不能单轴缩放/变形？（原版动画机制）

### ModelPart 支持的全部变换（1.21.1 实测字段）

```
public float x, y, z;            // 平移
public float xRot, yRot, zRot;   // 旋转（欧拉角，弧度）
public float xScale = 1, yScale = 1, zScale = 1;   // 三轴独立缩放
```

`render()` 里的顺序是 translate(pivot) → rotate → **scale** → translate(-pivot)，所以
**缩放是绕该 part 的 pivot 进行的**，且**可以单轴**（`yScale = 0.05f` 就只压扁 Y）。

**但"变形"只有这一种形式**：MC 的模型是刚性盒，没有蒙皮、没有顶点动画、没有剪切/弯曲。
想做出"弯曲的眼皮/舌头"，唯一办法是**切成 2–3 段，各段给不同角度**（原版鱿鱼触手、
末影龙翅膀都是这么做的）。

### 眼皮三种做法对比

| 方案 | 一行代码的量级 | 视觉效果 | 前置条件 |
| --- | --- | --- | --- |
| **平移（推荐）** | `lid.y = -2.0f`（睁）/ `0f`（闭） | 眼皮从上往下滑，盖住眼睛——最像眨眼 | 无，**现在就能用**（pivot 在中心也不影响平移） |
| 旋转 | `lid.xRot = -1.3f` | 眼皮绕轴翻下来，带厚度与透视变化，最自然 | **pivot 要挪到眼睛上缘** (y=21.5, z≈−23.25)</br>现在在中心，转起来会把眼皮甩进脑袋里 |
| 单轴缩放 | `lid.yScale = 0.05f` | 从**中心**向中间压扁，看着像"眼皮缩没了"或"眯眼"，不像闭眼 | 无，但不推荐单用 |

**结论**：单轴缩放技术上完全可用（这是 1.20.5 起 `ModelPart` 的原生能力），但对眼皮来说
**平移最省事、旋转最自然、纯缩放最不像**。推荐 `平移为主 + 极轻微 yScale（0.85~1.0）` 做质感，
不必为了"能不能缩放"去改 pivot。

### 动画怎么驱动（没有时间轴）

原版没有关键帧系统，所有动画都是**每帧在 `setupAnim` 里改数值**：

- 眨眼：`ageInTicks` 取模做周期（每 80–160 tick 眨一次，闭合 3–4 tick）
- 瞳孔：`netHeadYaw / headPitch` 的余量做偏移（±0.2px），可叠低频扫视
- 下颚：外部状态位（被打 / 说话）驱动 `jaw.xRot`
- 耳朵 / 尾巴：`ageInTicks` + `limbSwingAmount`

这些都是纯客户端计算，不需要网络包，也不需要 GeckoLib。

## 十六、"外移瞳孔会悬空"的成因与解法（2026-10-27 04:16 (UTC+8)）

### 为什么会悬空

瞳孔现在是 **0.05px 厚的薄片**（`z −23.10 … −23.05`）。只要它离开眼白表面，从任何斜角都会
看到"薄片边缘 + 背后的缝"——这就是 Blockbench 视口里明显的悬空感。这与 z-fighting 是
同一个问题的两端：

- 贴太近（≤0.02px）→ 深度缓冲打架 → 真机闪烁
- 拉太开（≥0.10px）→ 薄片悬空 → 侧缝可见

**单靠调 z 无解**，因为薄片没有厚度去填这段缝。

### 解法：把瞳孔从"薄片"改成"柱体嵌入"

让瞳孔后半段**插进眼白内部**——只有前表面露出，侧面被眼白包住，自然没有缝：

| 部件 | 建议 z 范围 | 厚度 | 说明 |
| --- | --- | --- | --- |
| `eye_lid_*` | **−23.42 … −22.42** | 1.00 | 最外层；闭眼时能盖住瞳孔 |
| `eye_pupil_*` | **−23.28 … −22.85** | 0.43 | 前表面距眼白 0.16、距眼皮 0.14；**后段 0.16 嵌在眼白里** |
| `eye_sclera_*` | −23.12 … −22.12 | 1.00 | 不动 |

三个验收点：

1. **不闪**：三层前表面两两间隔 0.14 / 0.16，远超 0.10 的安全线；
2. **不悬空**：瞳孔侧壁从 −23.28 到 −23.12 那段露在外面（0.16px 的短柱），再往里全被眼白包住——
   视觉上是"嵌在眼球上的黑点"，不是飘着的贴纸；
3. **闭眼不穿模**：眼皮前表面 −23.42 在瞳孔前表面 −23.28 之外，眨眼时瞳孔不会顶出眼皮。

### 两点提醒

- **BB 视口 ≠ 游戏内**：0.10px = 0.00625 格，第三人称 3–4 格距离下几乎不可见。但既然"柱体"
  方案能同时消除两个问题，就没必要接受这个折中。
- **加厚会改变 box UV 展开**：d 从 0.05 → 0.43，UV 布局宽 `2*(w+d)` 从 2.1 → 2.86（仍取整到 3），
  区域 `(45,63)` 3×2 够用，但要重生成后核对正面 UV 仍指到黑色像素（`(26,26,26)`）。

### 备选（当不想加厚时）

- 把瞳孔直接画进眼白贴图（`eye_sclera` 正面 UV 区画青蓝+黑瞳），牺牲"可动瞳孔"，换取零悬空零闪烁；
- 或用 `yScale/xScale` 让薄片"看起来有厚度"——不可行，缩放不会产生侧壁。
