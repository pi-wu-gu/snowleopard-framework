# 在 PCL2 整合包实例里跑雪豹 + 迁移 AI 家 · 可行性分析

> 时间：2026-10-28 13:30 (UTC+8)
> 对象：`C:\Users\w0801\PCL2\.minecraft\versions\夯空学AI测试区`
> 基线：雪豹框架 1.15.2（内嵌 core 0.7.1），dev 真机 58 PASS / 0 FAIL

## 一、结论

**可行，但不是"复制文件夹就能跑"**。数据层几乎零阻力（家目录无绝对路径、体量 7 MB），
阻力集中在三处：一个必须改的开关、一套必须排除的坐标类文件、288 个 mod 的未知冲突面。

| 项 | 判定 |
| --- | --- |
| 家目录整体搬迁 | ✅ 可行（已验证无绝对路径耦合） |
| 目标实例能加载雪豹 jar | ✅ 可行（同 MC 1.21.1 / NeoForge 21.1.x / Java 21） |
| 目标实例能跑 AI | ⚠️ **需要先改一处代码**（AI 开关与验收开关绑在一起） |
| 288 mod 共存 | ⚠️ 需真机实测，静态无法保证（相机/渲染剔除/UI 三类风险） |
| 复制后"记忆与对话延续" | ⚠️ 部分可延续，**世界坐标类必须丢弃** |

## 三、为什么数据层可行

1. **数据根与世界解耦**：雪豹全部持久化在 `<gameDir>/snowleopard/` 下，`ids/<模型ID>/` 是一家、
   `shared/` 是跨家共享面。它不写注册表、不写 world 目录。
2. **没有绝对路径耦合**：对 `ids/clienttest` 与 `shared` 全量 grep `C:\Users` / `C:/Users` / `run-server`
   **零命中**——说明记录里只有相对结构（图只存文件名、历史只存名字），搬过去不会指向原机器路径。
3. **体量可控**：家 6.0 MB（大头是 vision 下的 PNG）+ shared 799 KB。
4. **单人游戏就是"内嵌服务端 + 客户端同进程"**：AI 宿主跑在服务端线程，视觉后端恰好要求
   "同维度、128 格内有玩家"——单人场景下这条件天然成立，比多人服还简单。

## 四、三个真障碍

### A. AI 开关与验收开关是同一个（唯一必须改代码的地方）

现状（`SnowLeopardMod` 第 114 行）：

```
boolean clientTest = Boolean.getBoolean("snowleopard.clienttest");
AiHost.init(gameDir, core, clientTest);
```

也就是**没有"只跑 AI、不跑验收"的模式**。想在整合包里启用 AI，只能加系统属性
`-Dsnowleopard.clienttest=true`，但同一开关还连带三件事：

| 连带行为 | 在真实存档里的后果 |
| --- | --- |
| `ClientSmokeTest` 于玩家进服后跑 58 条断言 | 会**传送玩家**、造僵尸猪灵/史莱姆、破坏方块、造箱子——不能出现在玩家的正式存档里 |
| `PlayerTestArea.ensureBuilt` | 在真实存档里建 2×2 区块棋盘格测试塔 + 石英墙 + 萤石 |
| vision.backend=stub 分支 | 若误配 stub，画面是假的（能力级仍报 L0） |

**必须拆成两个开关**：`ai.enabled`（读配置文件，生产用）+ `clienttest`（只做验收）。
改动量小（`SnowLeopardMod` 一处判断 + 一个配置读取），但不改就跑不了——这是本次迁移唯一的前置代码工作。

### B. 家数据里三类"不能直接搬"

| 文件 | 内容 | 搬过去会怎样 | 处置 |
| --- | --- | --- | --- |
| `shared/playtest-area.json` | `{"floorY":-60}` | 新存档地板不是 -60 → 测试区与"挖穿掉落"判定全错 | **删**，由新存档重建 |
| `shared/avatars.json` | 载体实体 UUID + 名字 + 定时 | 新世界没有这个实体 → 登记悬空，模型无法绑载体 | **删**，进游戏重新绑定 |
| `shared/run/*.lock` | 进程锁 | 新进程会以为"会话被占" → 刷"会话开不了"、自检唤醒 FAIL | **排除**（当前目录为空，属预防） |
| `ids/<ID>/core_binding.json` | 玩家 UUID + 名字 | 同账号 UUID 不变 → 绑定继续有效 | 搬 |
| `memory/`、`memory-raw/`、`host/history.jsonl`、`groups/`、`notes/`、`todo/`、`shared/chat/` | 纯文本 | 无副作用，记忆与对话可延续 | 搬 |
| `ids/<ID>/vision/*.png` | 截图（占 6 MB 大头） | 无害但体积大 | 建议只留最近 20 张（`keep_images` 的既有策略） |

### C. 288 mod 的冲突面（静态无法判定，必须实测）

| 风险点 | 机制 | 表现 | 应对 |
| --- | --- | --- | --- |
| 越肩 / 相机类 mod | `vision/shot` 靠 `setCameraEntity(载体)` 抓一帧 | 抓到的可能是越肩视角或完全黑屏 | 截图验收时必须肉眼比对；必要时在测试时停用越肩 |
| entityculling | 对不可见实体直接跳过渲染 | 载体在画面外时"拍不到"，或被判定为不存在 | 载体在视野内再拍；失败会走 3 秒兜底 + 失败原因日志 |
| ModernUI | 重写 Screen 渲染管线 | 核心界面（CoreScreen）自绘，可能错位或不可点 | 打开核心界面点一次按钮即可确认 |
| 288 mod 内存 | 常规整合包要 6–8 GB，host 还有 LLM 线程 | OOM 或卡到断言超时 | 分配堆 ≥6G；截图超时已放宽到 5s |

## 五、落地步骤（若决定做）

1. **改代码**：拆开关——新增 `ai.enabled`（建议复用 `config/snowleopard-llm.json` 里加一段，
   或独立小文件），`AiHost.init` 用 `aiEnabled`；`clienttest` 只控制验收相关。
2. **构建并拷贝**：`gradlew :shell:build` → 把 `snowleopard-neoforge-1.21.1-1.15.2.jar` 放进目标 `mods/`。
3. **带配置**：复制 `config/snowleopard-llm.json`（**含密钥，注意不要外发/入库**）。
4. **复制家**：写好排除清单（见 §四B），`ids/<ID>` 与 `shared` 一起拷。
5. **开档**：新建世界（或指定存档），进服 → 右键载体完成绑定 → 触发一次会话。
6. **验收 5 项**（缺一项就等于没跑通）：
   启动日志出现"AI 执行端就绪 / 路由 / 视觉能力 / 骨架 13 组" → 模型能 `avatar_bind` →
   说一句话能被 `chat_send` 回 → `vision_shot` 出真图 → 记忆里出现本轮记录。

## 六、三个"看起来成功其实没跑"的坑（按经验排序）

1. **host 没启用**：日志里没有 `[host] AI 执行端就绪`，模型完全不说话，但游戏一切正常。
2. **LLM 配置读不到**：`config/snowleopard-llm.json` 没拷 → host 如实报"未配置"并停用（不会静默），
   但容易被忽略；缺 `roles` 则会静默回落到第一个 provider。
3. **实体被渲染剔除**：截图成功但画面里没有载体（只有地形），模型据此得出错误结论。

## 七、工作量估计

| 阶段 | 内容 | 估计 |
| --- | --- | --- |
| 拆开关 | 1 处判断 + 1 个配置项 + 断言不变 | 30–40 分钟 |
| 复制脚本 | 排除清单 + 校验（家文件数/体量对得上） | 20 分钟 |
| 整合包真机 | 288 mod 启动、装 jar、开档、5 项验收 | 60–120 分钟（含试错） |

## 八、建议

先做**拆开关**这一步——它独立有价值（生产服也迟早要），且不依赖整合包环境。
拆完之后，迁移就退化成"拷 jar + 拷配置 + 拷家（带排除）"三件机械动作。
288 mod 的冲突只能靠真机试，不建议为了"先跑起来"而简化验证：相机与渲染剔除这类问题，
**表现是"AI 说了错话"而不是"报错"**——这正是记忆里最贵的一类坑。
