> 用户命题：① 物品「受限核心」（测试期用木棍合成），右键放出可绑定一个模型（放出时出现界面
> 选择或创建，**未确认创建则不消耗**）；② 载体加经验条，可消耗经验回血（不挂钩等级、仅消耗指定量、

> ⑤ 玩家手持核心打开设置界面设置载体信息（唤醒间隔等）。

**总体可行，但工作量集中在一个此前完全空白的地方：图形界面。** 粗略 **7.5–8.5 天**。

## 二、模型解析结果（决定 ① 的形态）

`受限核心.bbmodel`：`meta.format_version = 5.0`、`model_format = java_block`、`resolution = 16×16`。

| 项 | 实测 |
| --- | --- |
| 元素数 | 10 个 cube |
| 主体 | `[7,7,7] → [9,9,9]`（2×2×2 格），内嵌 `[7.5,7.5,7.5] → [8.5,8.5,8.5]` |
| 八个角块 | 0.95~1.05 见方，分布在中心四周（像"约束装置"的八个卡扣） |
| 整体包围盒 | `6.95 → 9.05` ≈ **2.1×2.1×2.1 格**，中心恰在方块中心 `(8,8,8)` |

**关键判断**：这是**方块模型**（`java_block`），不是实体模型。所以"右键放出"落地的是一个**方块**，
不会是"变出一只猫"。这与现有载体 `snowleopard:avatar`（实体）是两套东西，必须先定关系（见 §三.1）。

尺寸上 2.1 格超出 1×1×1 的方块碰撞箱——**视觉会比碰撞箱大**。要么接受（穿模感），要么把比例缩到
1 格内（改 `display` 缩放），要么注册成"大号方块"（`noOcclusion` + 自定义 VoxelShape）。建议：
**保留原比例，碰撞箱仍按 1 格**（装置悬浮感的代价很小），并在文档里写明。

## 三、六项需求逐条拆解

### 3.1 ① 与 ②：核心方块 与 载体实体 的关系（**必须先裁决**）

现有链路是：`avatars.json` 记录 `uuid ↔ modelId`，`uuid` 指向一个 `snowleopard:avatar` **实体**。
新核心是**方块**。两者有三种接法：

| 方案 | 做法 | 代价 | 我的看法 |
| --- | --- | --- | --- |
| **A 方块=家（推荐）** | 放出核心方块 = 给某个 modelId 立"锚点"，同时 spawn 一个 avatar 实体绑在它上面；方块被破坏 → 解绑 + 实体回收 | 多一个"锚点"概念，但与"主载体唯一"不冲突 | 契合"受限核心"这个名字：**模型被约束在这个核心里** |
| B 方块=身体 | 模型直接以方块形态存在于世界（不可移动） | 现有 13 组工具（move/interact/视野）全部失效 | 等于废掉已有能力，不建议 |
| C 方块=纯物品功能 | 右键弹界面直接绑定/召唤，方块只是"已用掉的凭证" | 模型文件白做 | 与模型不符 |

**建议 A**，并且把"一个 modelId 至多一个核心"做成硬约束（与 `primary` 主载体唯一同源）。

### 3.2 ② 的原子性：「未确认创建则不消耗」

这是整条链路唯一会造成**数据事故**的地方，必须写死：

1. 客户端右键 → **不发消耗**，只发"我想开界面"（纯客户端 `Screen`）。
2. 界面里选/填 modelId → 客户端发一条 `CoreBindRequest(itemStackSlot, modelId, action)`。
3. 服务端收到后**二次校验**：物品还在手上？是核心？该 modelId 是否已占？坐标可放置？
   → 任一不过即拒（回执说明原因），**物品不动**。
4. 全部通过才 `shrink(1)` + 放置方块 + 登记 `avatars.json`（三者同一 tick，失败回滚）。

> 铁律：**客户端界面只是"填写表单"，不是"授权"**。任何"界面里点确定就算数"的实现都会被
> 刷物品（重发包 / 断线重连 / 双开）。这与现有 `confirm_token` 两段式是同一思路。

### 3.3 ③ 经验池与消耗回血

Mob 没有经验（原版只有 `Player` 有 `Experience`）。所以自建：

| 项 | 设计 | 理由 |
| --- | --- | --- |
| 存储 | 实体字段 `xp`（int，0–1000）+ `xf` 浮点？不需要浮点 | 与等级完全解耦（用户要求"不挂钩等级"） |
| 同步 | `SynchedEntityData` 一个 int / 前端用 float 显示条 | 沿用刚做的 4 浮点写法与阈值策略 |
| 来源 | 击杀生物给（按血量折算）、玩家投喂经验瓶、核心界面测试期可充 | **没有来源的"可消耗"就是空账**，必须同时给 |
| 消耗 | `avatar_heal(cost)`：cost 经验 → 恢复 `cost × K` 血；`K` 缺省 0.5（2 经验 = 1 血） | 比值必须单点定义 |
| 速率 | 每 tick 最多回 `0.5` 血（= 10 血/秒），并限制"每秒最多消耗 20 经验" | 否则模型一口气把经验烧光，玩家看不见过程 |
| 上限 | 回不超过 `getMaxHealth()`；死亡时清空经验（与"死亡即解绑"一致） | 避免死亡刷经验 |

**显示位置**（需裁决，三种代价差很大）：

| 方案 | 实现 | 代价 |
| --- | --- | --- |
| A 头顶字符条 | `setCustomName` 显示两行（`████── 12/20` + `◆◆◆─── 60/1000`） | **最省**，无渲染代码；缺点：远景不可读、占名字栏 |
| B HUD | 准星附近画条（`RenderGuiEvent`） | 中；只在看着它时显示，干净 |
| C 世界空间条 | 自己算投影画四边形 | 高（要处理遮挡/缩放） |

建议**先 A（今天就能看见），后续升级 B**。

### 3.4 ④ 饥饿值 + 进食 + 右键投喂

| 项 | 设计 |
| --- | --- |
| 存储 | `hunger`（0–20）+ `saturation`（可选，缺省不做） |
| 递减 | 每 30 秒 -1（可配）；疾跑/挖掘加倍？**建议先只按时间**，参数化了再谈 |
| 影响 | `hunger <= 0` → 不能用经验回血（"饿得回不动"）+ 移速 ×0.85；`hunger >= 6` 才能自然回血 |
| 自行进食 | 新工具 `avatar_eat(slot?)`：从背包取"食物"（`DataComponents.FOOD` 判定，1.21 已确认用组件而非 `isEdible`），按 `nutrition` 回饥饿、`saturationModifier` 回血 |
| 右键投喂 | 手持食物右键载体 → 消耗 1 个 → 回饥饿 + 少量血 + 一条回执 |

**右键语义冲突（必须处理）**：`AvatarEntity` 现在右键会触发唤醒（`onInteract`）。加入投喂后优先级要定死：

```
手持"食物" → 投喂（不唤醒）
空手       → 唤醒（现有行为）
手持核心   → 打开核心界面（见 ⑥）
其他物品   → 唤醒（保持现状）
```

否则玩家想喂它一次，结果触发一轮 AI 会话（还烧 token）。

### 3.5 ⑤ 饥饿自动唤醒 + 定时唤醒

- **定时唤醒：已存在**。`AvatarStore.Entry.intervalSec` + `nextFireAt`，下限 **60 秒**（`MIN_INTERVAL_SEC`），
  由 `AvatarWake.onServerTick` 每 20 tick 扫 `due()`。所以这条只需"让玩家能改这个值"（见 ⑥）。
- **饥饿唤醒：新增**。放在同一个 20 tick 扫里：`hunger <= 6` 且距上次饿醒 > 5 分钟 → 登记唤醒，
  prompt 写"你饿了（3/20），背包里有 <前 3 个食物名>，或叫玩家投喂"。

> **必须独立节流**：唤醒配额是"一小时内 48 次"（真机撞过满额，玩家只看到"唤醒被拒绝"）。
> 饥饿唤醒若严格按 `hunger` 逐点判断，会在掉到阈值期间反复触发 → 一定要"5 分钟冷却 + 每次掉到阈值只报一次"。

### 3.6 ⑥ 手持核心打开设置界面

复用的是 ② 的 GUI 骨架，增量很小：

- 界面内容：载体列表（`AvatarStore.all()`，本次已为 `/snowleopard avatar list` 加过）
  → 选中一个 → 编辑"唤醒间隔（≥60s）/ 开关定时 / 显示名 / 是否主载体" → 提交。
- 服务端校验：modelId 存在、间隔 ≥60、名字不重名（`nameTaken`）→ 写 `avatars.json`。
- **不放进 GUI 的能力**：`sense open` / `pick`（"谁开这台机器"该由模型自己决定，运维命令也不代劳）。

## 六、需要裁决的口径（一次定完即可开工）

1. **核心方块与载体的关系**：走 A（方块=家，同时 spawn avatar 实体）？（我推荐 A）
2. **经验条显示**：先 A（头顶字符条）还是直接做 B（HUD）？
3. **经验来源**：击杀给（按血量折算）+ 经验瓶 + 界面测试充值——三条都要，还是先只做其中一条？
4. **回血兑换比与速率**：2 经验 = 1 血、每 tick 最多 0.5 血、每秒最多耗 20 经验——可以吗？
5. **饥饿是否影响能力**：只"不能回血"，还是要连带降移速（×0.85）？
6. **右键优先级**：食物→投喂 / 空手→唤醒 / 核心→界面 / 其他→唤醒——按这个？
7. **测试期合成配方**：木棍 ×3 + 铁锭 ×1（或直接 8 木棍围一圈）？给一个具体形状。
8. **界面范围**：只做"载体列表 + 唤醒间隔/开关"，还是这版就把经验/饥饿也放进界面显示？
