## 零、前提修正：本项目**独立**，不接星期五

这条不是补充说明，是**改前提**——之前两份文档里"真正的执行端在星期五那一层"的措辞必须作废。受影响三处：

| 原表述 | 修正后 |
|---|---|
| 注入/唤醒的执行端 = 星期五 | 执行端 = **接入方（任意 LLM 宿主）**，本项目只出事件与契约；**没有接入方时请求停在 pending 并可查，绝不假装执行** |
| "宿主（星期五那一层）调用 pull/ack" | "接入方调用 pull/ack"，接口与本项目无关，谁接入谁负责 |
| 唤醒 = 模型→模型 请求 | 唤醒有**三个外部触发源**（玩家互动 / 时钟 / 聊天提及），模型→模型只是其中之一 |

**独立性的实际含义**：本项目提供「事件源 + 工具 + 持久化」，LLM 在哪跑、怎么跑不在本项目职责内。
所以下面所有"唤醒"都只到 **`WakeRequest` 落盘 + 可查** 为止。

## 一、结论

| 需求 | 判定 | 关键结论 |
|---|---|---|
| 创建新实体（载体），复用**豹猫**模型，无原版 AI | **可行，且比预想更干净** | `OcelotModel` 的泛型上界是 **`Entity`**（不是 `Ocelot`）→ 可直接 `OcelotModel<Avatar>` 套在自己实体上，**不必继承 `Ocelot`**（因此白拿不到驯服/繁殖/攻击鸡那些原版行为）。只需自写 ~15 行 renderer；尺寸照豹猫 0.6×0.7；`registerGoals()` 留空 + `setNoAi(true)`，位移由核心写速度 |
| 绑定后可被实体互动唤醒 | 可行 | `PlayerInteractEvent.EntityInteract`（右键）+ `LivingIncomingDamageEvent`（被打）；需**每实体冷却**，否则玩家连点=每秒一次唤醒 |
| 可定时唤醒 | **可行，但不能挂实体 tick** | 区块卸载后实体不 tick → 定时会**静默失效**。必须服务器级调度器 + 独立持久化（§3.2，本段最大的坑） |
| 相关信息绑定实体 | 可行（要定权威） | 实体 NBT 存绑定，**但调度信息必须以盘上调度表为权威**（未加载的实体查不到 NBT）；启动时比对，冲突以调度表为准并 WARN |
| 发送消息附带 ID，有名称则用名称 | 可行 | 身份取自实体：`[雪豹·<名称>]`；无名称退化为 `[雪豹·<模型ID>]`；名称冲突时补短 ID |
| 被提到名称时唤醒一次，**ID 不唤醒** | 可行 | 名称匹配用**子串**（中文无词边界），但要求名称长度 ≥2；**只玩家来源的消息触发**（模型自己说的话提到自己会引发风暴） |

**一句话总结**：三条唤醒源本身都不难，难的是三件"看起来能跑、出事才发现"的事——
**定时不能挂实体 tick**、**绑定/调度必须定唯一权威**、**提及唤醒必须排除模型来源**。
豹猫这条裁决额外送来一个好消息：`OcelotModel` 泛型宽松，**复用外观 ≠ 继承原版行为**（§2.4）。

## 二、新实体（载体）

### 2.1 注册面（三处，缺一就崩或看不见）

| 面 | 做什么 | 备注 |
|---|---|---|
| `DeferredRegister<EntityType<?>>`（注册表 `Registries.ENTITY_TYPE`，id `snowleopard:avatar`） | 声明实体类型：尺寸 0.6×1.8、`clientTrackingRange` 适当、`fireImmune` 视裁决 | 注册需 **mod 事件总线**（`ModContainer#getEventBus()`），不能挂 `NeoForge.EVENT_BUS` |
| `EntityAttributeCreationEvent`（mod 总线） | `put(AVATAR, Mob.createMobAttributes().add(MAX_HEALTH,20).add(MOVEMENT_SPEED,0.25).add(...))` | 缺这条 → 生成即 `NoSuchElementException` |
| `EntityRenderersEvent.RegisterRenderers`（**仅客户端**，`Dist.CLIENT`） | 自写 `MobRenderer<Avatar, OcelotModel<Avatar>>`，贴图指向原版 `textures/entity/cat/ocelot.png` | 服务端不加载渲染类；用 `@EventBusSubscriber(value = Dist.CLIENT)` 隔离 |

**"复用原版模型/材质"的边界**：复用**模型类与贴图**，不复用原版实体类（用户明确"创建新的实体"）。
豹猫这条裁决正好证明这个边界是可行的，而且必须这么切——见 §2.4。

尺寸照抄豹猫 **0.6 × 0.7**：碰撞箱与模型比例要一致，否则载体看起来会浮空或陷地。代价是**命中箱偏小**
（玩家右键要瞄准一只猫大小的目标）；嫌难点就在 renderer 里 `scale(1.3f)` 并把实体尺寸调到 0.6×0.9 一起改，
**不要只改一头**。

### 2.2 无原版 AI 的三条陷阱

1. **`Mob.checkDespawn` 会远距静默 `discard()`**（本项目已踩过）：绑定载体一旦被丢掉，绑定关系就没了，
   而且**不发死亡事件、不报错**。必须 `setPersistenceRequired(true)`（或 override `removeWhenFarAway`）。
2. **`setNoAi(true)` 是否连带关掉 `travel`（物理）需要实测**：如果关了，位移完全由核心写速度——这正好和
   现有 Mover 的路子一致（Mover 唯一底层就是引擎物理），但要确认"没有 AI 时重力/碰撞仍在"。
3. **死亡 vs 卸载必须区分**：死亡 → 解绑并记原因；区块卸载/世界保存 → **不算解绑**。
   混在一起会出现"实体还在但模型以为它死了"的幽灵绑定。

### 2.3 绑定信息存哪 —— 必须定唯一权威

「相关信息绑定实体」的正确实现不是"只存实体 NBT"，因为**调度器要处理未加载的实体**（§3.2）：

| 数据 | 权威位置 | 理由 |
|---|---|---|
| 绑定的模型 ID | 实体 NBT（`snowleopard:model_id`） | 跟着实体走，实体在哪绑定就在哪 |
| 显示名称 | 实体 NBT（优先用原版 `CustomName`，不另造一套） | 复用原版命名牌机制，玩家能用命名牌改名 |
| 定时策略 + `nextFireAt` | **盘上调度表**（`<storage>/wake-schedule.json`） | 未加载的实体读不到 NBT，但定时仍需按时判断 |
| 实体 UUID ↔ 模型 ID 反查 | 调度表内一并记 | 避免"扫全服实体"这种必然不完整的枚举 |

**冲突裁决**：加载时（`EntityJoinLevelEvent`）比对 NBT 与调度表，不一致**以调度表为准**修正 NBT 并 `WARN`。
理由：调度表能覆盖未加载场景，NBT 不能；两个都"看起来对"时，选覆盖面大的那个，并把漂移暴露出来。

### 2.4 豹猫这条裁决的连带影响（含一个好消息）

查过 1.21.1 的实际签名：

```
net.minecraft.client.model.OcelotModel<T extends Entity> extends AgeableListModel<T>
net.minecraft.client.renderer.entity.OcelotRenderer extends MobRenderer<Ocelot, OcelotModel<Ocelot>>
```

**好消息**：模型的泛型上界是 `Entity`，不是 `Ocelot`。所以 `OcelotModel<Avatar>` 编译期成立，
**我们的载体不必 `extends Ocelot`** —— 这一点很关键，因为继承 `Ocelot`（它是 `Animal`）会白拿一堆必须再拆掉的行为：

| 若继承 `Ocelot` 会白拿 | 后果 | 所以不继承 |
|---|---|---|
| `Animal`：`BreedGoal` / `FollowParentGoal` / `PanicGoal` / `TemptGoal(fish)` | 载体自己乱跑、被鱼吸引、和别的豹猫繁殖 | — |
| `Ocelot`：`NearestAttackableTargetGoal<>(Chicken)` | 载体去猎鸡（"所有行为由核心控制"直接破功） | — |
| `Ocelot.mobInteract`：喂鱼 → 生成一只**猫**并播放信任动画 | 玩家右键本来要唤醒，结果刷出一只猫 | — |
| `MobCategory.CREATURE` 参与生物上限 | 载体与真豹猫抢 spawn cap | 改 `MobCategory.MISC` 且**不注册 spawn placement** |

**仍要自己写的那 15 行**：`OcelotRenderer` 绑死了 `Ocelot`，所以不能直接用；但模型可以复用：

```java
// 仅客户端；贴图用原版，零新资源
public final class AvatarRenderer extends MobRenderer<Avatar, OcelotModel<Avatar>> {
    private static final ResourceLocation TEX =
            ResourceLocation.withDefaultNamespace("textures/entity/cat/ocelot.png");

    public AvatarRenderer(EntityRendererProvider.Context ctx) {
        super(ctx, new OcelotModel<>(ctx.bakeLayer(ModelLayers.OCELOT)), 0.4f);
    }

    @Override
    public ResourceLocation getTextureLocation(Avatar entity) {
        return TEX;
    }
}
```

**需要真机看一眼的一点**：`OcelotModel` 里有 `SITTING_STATE` 这类姿态常量，若 `setupAnim` 读取了豹猫专属状态
（坐姿等），我们的实体不是 `Ocelot`，可能永远渲染成站姿或静止姿势怪异。泛型上界是 `Entity` 说明**不会有运行期 cast 崩溃**，
但"看起来对不对"必须眼睛确认——这是本段唯一需要在 M13-1 里肉眼验的事。

**音效**：`Ocelot` 的叫声不跟随模型，载体默认**静默**（不实现 `getAmbientSound`），避免"猫叫来自一个不动的载体"这种错位感。

**四处签名已核实**（`javap` 查 1.21.1 dev jar，2026-10-23 23:48）：
`OcelotModel<T extends Entity>` ✓ · `OcelotRenderer extends MobRenderer<Ocelot, …>` ✓ ·
`ModelLayers.OCELOT` ✓ · `MobCategory.MISC` ✓ · 贴图 `assets/minecraft/textures/entity/cat/ocelot.png` ✓（在 client-extra 资源 jar 里）。

## 三、三类唤醒源

### 3.1 互动唤醒（右键 / 被打）

```
PlayerInteractEvent.EntityInteract  → 右键载体（交互手、手持物、玩家）
LivingIncomingDamageEvent           → 载体被攻击（伤害来源、伤害量）
```

两者都转成 `WakeRequest`：`prompt` 写清"谁、用什么、在哪"，`reason` 写 `interact:right_click` / `interact:attacked`。

- **每实体冷却 10 秒**（玩家连点右键/连续挥砍 = 每秒一次唤醒，不加冷却会被刷）。
- 一次"交互窗口"内只唤醒一次：冷却期内重复互动**不新建请求**，只把计数记进已有请求的 outcome（可选）。
- **被打要不要唤醒**：被攻击也是信息（"有人打我"），但刷怪塔/自动伤害会变成骚扰源。
  → **裁决（2026-10-23 23:42）：可配置**，配置项 `wake.on_damage` 默认开；关掉后仍记审计（信息不丢）。

### 3.2 定时唤醒（本段最大的坑）

**不能挂实体 tick**。`Mob.tick` 只在实体所在区块加载时执行；玩家走远、区块卸载 → 实体不 tick → 定时静默失效。
而且这种失效**没有任何报错**，只表现为"说好每 10 分钟唤醒一次，玩家离开后就再也不唤醒了"。

正确做法：

```
服务器级调度器（ServerTickEvent.Post 每 20 tick = 1 秒扫一次，只看最小堆顶）
  ├─ 状态：<storage>/wake-schedule.json（entityUuid, modelId, intervalSec, nextFireAt, enabled, lastResult）
  ├─ 到点 → 查实体是否加载
  │    ├─ 已加载 → 发 WakeRequest，nextFireAt += interval
  │    └─ 未加载 → **skipped 记原因**，nextFireAt += interval（不堆积、不补发）
  └─ 防止"补偿风暴"：绝不做 "错过 N 次就补 N 条"
```

- **时间基**：用**现实时间**（epoch 毫秒），不用游戏时间——游戏内时间会被 `/time set`、睡觉、服务器暂停打乱。
- **未加载时跳过而非补发**：唤醒的目的是"让模型在场景里干活"，实体不在场景里唤醒了也没法干；
  补发会在玩家回来那一刻炸出一串请求。跳过并记 `skipped:not_loaded` 是诚实降级。
- **最小间隔**：定时唤醒最短 60 秒（再短就是轮询，等于没有意义地烧 LLM 预算）。
- 存档迁移：`nextFireAt` 存绝对时间，服务器停机跨天也不会漏。

### 3.3 名称提及唤醒（ID 不唤醒）

订阅与聊天记录**同一个 `ServerChatEvent`**（所以本功能依赖聊天工具组的记录能力，顺序在 M13 而非 M12）。

规则：

| 规则 | 取值 | 理由 |
|---|---|---|
| 匹配对象 | 实体**显示名称**（`CustomName` 优先，其次默认名） | 用户明确 |
| **不匹配** ID | 模型 ID / UUID 都不作为**唤醒**关键词 | 用户明确"ID 不唤醒"；ID 是内部标识，不该成为外部遥控器。<br>**但编号被提及会给一条"提示"**（不进唤醒，见 `聊天工具组可行性分析` §2.6）——提示是一行字，唤醒是一个回合 |
| 匹配方式 | **子串**，大小写不敏感；名称长度 **< 2 字符禁止作为可唤醒名** | 中文无词边界，"雪" 会在"下雪了"里误触 |
| 触发来源 | **只玩家来源**（`PLAYER`） | 模型 `chat_send` 里提到自己名字会立刻自触发 → 无限风暴（与 chat 注入只认 PLAYER 同一条规则） |
| 一条消息多次提及 | **只唤醒一次** | 用户明确"唤醒一次" |
| 多实体同名 | 全部唤醒，**回执里列出实际命中的实体**；同时**创建时禁止重名**（载体层校验） | 群组里"同名全收到"是有意设计；实体唤醒里重名会让"谁被唤醒了"无法回答 |
| 冷却 | 每实体 10 秒（与互动共用冷却窗口） | 玩家连续刷同一句会变遥控器 |

## 四、消息身份：名称优先，ID 兜底

```
有 CustomName  →  [雪豹·小白]        （玩家能看懂、能用命名牌改）
无 CustomName  →  [雪豹·selftest-m11]（退化为模型 ID，保持可追溯）
名称冲突       →  [雪豹·小白(m11)]    （短 ID 只在冲突时补，不污染常态）
```

三处都要用同一套身份解析（**只有一处实现**，别各写一份）：
① `chat_send` 的前缀 ② `ChatPush` 摘要里的归属 ③ 提及唤醒的回执。
> 这是"同一职责多实现必漂移"的直接应用：三处各拼一次名字，改一处就漂。

**"附带 ID"怎么理解**：用户要求"发送消息时附带 ID，如果有名称则使用实体名称"——两者不是并列，而是**先后**：
有名称用名称、没名称才用 ID。但为了让**追溯**不丢，建议 `chat` 记录里始终写完整 `modelId`（落盘字段），
只有**展示前缀**走"名称优先"。这样玩家看到的是名字，模型和日志看到的是 ID。

## 五、职责切分（修正版，无星期五）

| 层 | 负责 | 不负责 |
|---|---|---|
| **core** | `WakeStore` 六道闸、配额、幂等、`pending/complete` | 任何 MC 概念 |
| **壳（本仓）** | 载体实体、三类事件源、调度器、绑定/调度持久化、`chat` 记录与注入块 | 执行唤醒（没有 LLM） |
| **接入方**（本项目外，任意宿主） | 取 `pending()` → 跑模型 → `complete()`；`chat` 的 `pull/ack` | 绑定与调度判定（都由壳给） |

**外部触发的 `from` 约定**（重要）：玩家/时钟/提及都不是模型 ID，所以 `from` 用**带前缀的伪 ID**：

```
player:muyiyang      ← 玩家互动
clock                ← 定时
mention:muyiyang     ← 提及唤醒
```

绝不能借用某个真实模型 ID 当 `from`——那会让核心的"自唤起/成环/黑名单"判定全部失真。
同时：**黑名单只管模型 ID**（"我不接受谁唤起我"防的是模型互相骚扰），玩家触发不受黑名单限制。

## 六、风险表

| # | 风险 | 处置 |
|---|---|---|
| 1 | 定时唤醒挂实体 tick → 玩家走远后静默失效 | 服务器级调度器 + 盘上 `nextFireAt`（§3.2） |
| 2 | 实体被 `checkDespawn` 静默 discard → 绑定凭空消失 | `setPersistenceRequired(true)`；死亡与卸载分开处理 |
| 3 | 绑定/调度双写漂移 | 调度表为权威，加载时比对并 WARN（§2.3） |
| 4 | 玩家连点右键/连击 → 唤醒风暴 | 每实体 10 秒冷却（三源共用） |
| 5 | 模型提到自己名字 → 自触发风暴 | 提及只认 `PLAYER` 来源 |
| 6 | 重名 → "谁被唤醒"无法回答 | 创建时禁止重名 + 回执列实际命中 |
| 7 | 短名误触（"雪"） | 名称长度 ≥2 才允许作为唤醒词 |
| 8 | 未加载实体补发堆积 | 跳过并记 `skipped:not_loaded`，不补发 |
| 9 | 新实体与现有实体组抢控制权 | 载体只受核心写速度；`sense`/`entity` 组对它照常可用（它就是个实体） |
| 10 | 复用豹猫模型导致客户端渲染崩 / 姿态怪异 | renderer 只在 `Dist.CLIENT` 注册；服务端类不触碰客户端类；姿态要在真机看一眼（§2.4） |
| 11 | 载体被当成真豹猫：玩家喂鱼、想撸、指望它会跑 | 不继承 `Ocelot`（§2.4）；尺寸小是既定代价；命中箱问题与 `scale` 一起调 |
| 12 | 载体自然生成进野外（看着像野猫，实为空壳） | `MobCategory.MISC` + **不注册 spawn placement**；断言里要查"世界里不会自发出现" |

## 七、验收断言草案（AvatarCheck + WakeSourceCheck，约 24 条）

```
① 载体（10）：注册成功且可取到 EntityType / 属性齐全（生成不抛） / 无 goal（getGoals 为空或 isNoAi）
   远距不 discard（造 200 格外仍存在）/ 死亡 → 解绑且有原因 / 卸载 → 不算解绑 / NBT 存 model_id
   尺寸 0.6×0.7（命中箱与模型一致）/ 不在 `MobCategory.CREATURE` 且无 spawn placement / 不继承 `Ocelot`（反射查父类）
② 互动唤醒（6）：右键主载体 → 一条 pending / 冷却内连点 → 仍只一条 / 被打 → pending（配关后 → 无）
   prompt 含玩家名与坐标 / 冷却过后再点 → 新一条 / **非主载体被右键 → 不产生请求**
③ 定时唤醒（5）：到点产生 pending / interval 正确推进 / **实体未加载 → skipped 且不堆积**
   最小间隔 60 秒下限（传更小 → 拒绝或抬到 60）/ 服务器重启后 nextFireAt 不丢
④ 提及唤醒（6）：名称命中 → 一条 WakeRequest / 同一句提两次 → 仍一条 / **模型来源消息提及 → 不触发**
   ID 提及 → **不产生 WakeRequest**（但产生一条提示，见 ChatCheck ⑦）/ 名称 <2 字 → 不作为唤醒词
   唤醒失败（配额满/在运行）→ 记原因，不重试
⑤ 身份（4）：有名称 → 前缀是名称 / 无名称 → 前缀是 ID / 重名创建 → 拒绝 / **命名牌改名撞已有名 → 拒绝并回滚**
⑥ 权威（3）：改 NBT 与调度表不一致 → 加载时以调度表为准 + WARN / 调度表缺失 → 从 NBT 重建 / 双向都有 → 不重复绑定
```

## 九、裁决（2026-10-23 23:42 (UTC+8) 用户已定，六条全部落定）

| # | 问题 | 裁决 | 落地要点 |
|---|---|---|---|
| 1 | 被打是否唤醒 | **可配置** | 默认**开**，配置项 `wake.on_damage`（建议放 `config/snowleopard-wake.json`）；关掉后 `LivingIncomingDamageEvent` 不产生请求，但**仍然记录到 chat/审计**（"有人打我"这条信息不能因为不唤醒就丢掉） |
| 2 | 定时粒度 | **按真实时间** | 只做"每 N 秒现实时间间隔"，用 epoch 毫秒；**不引入游戏内时间**（`/time set`、睡觉会打乱）；下限 60 秒 |
| 3 | 实体未加载时 | **跳过** | 记 `skipped:not_loaded`，`nextFireAt += interval` 正常推进，**绝不补发** |
| 4 | 重名 | **禁止** | 创建/改名时在载体层校验，命中已有名称 → 拒绝并给出冲突实体；`CustomName` 是玩家也能改的入口，所以**命名牌改名路径同样要校验**（`LivingEvent` 或 `EntityJoinLevelEvent` 兜一道） |
| 5 | 一个模型绑多个载体 | **按推荐**：允许多个，但只有一个**主载体**接收唤醒 | 绑定表加 `primary` 标志；非主载体只是"外观/位置存在"，不产生唤醒请求；切换主载体要显式工具或参数 |
| 6 | 复用哪个原版模型 | **豹猫** | `OcelotModel<Avatar>` + `textures/entity/cat/ocelot.png`；**不继承 `Ocelot`**（§2.4）；尺寸 0.6×0.7；`MobCategory.MISC` 且不注册自然生成 |

**第 5 条的连带影响**（写清楚免得后面对不上）：既然是"多载体 + 一个主载体"，那么
- **互动唤醒**：只有主载体被互动才唤醒（否则玩家摸一下装饰用的第二只猫也叫醒模型）；
- **提及唤醒**：名称匹配命中的若全是非主载体 → **不唤醒**，只在回执里说明"命中 X 个非主载体"；
- **定时唤醒**：调度表按**模型 ID** 一条，不按实体（否则 N 个载体 = N 份定时）。

**第 6 条的连带影响**：豹猫尺寸 0.6×0.7，右键命中箱小；且"豹猫"这个外形与"载体"语义容易混淆
（玩家会以为能喂鱼/能撸），所以 M13-5 真机验收要顺带确认：**右键不会被原版豹猫逻辑吃掉**（我们不继承 `Ocelot`，
理论上 `mobInteract` 是我们的，但 `PlayerInteractEvent.EntityInteract` 与我们自己的 `mobInteract` 谁先谁后要在真机确认一次）。

## 十、本版没做的（明确记账）

- **没有任何执行器**：本项目不实现 LLM 会话驱动。所有唤醒只到 `WakeRequest` 落盘 + `pending()` 可查为止。
- **定时唤醒不做"每天固定时刻"**（裁决 2 只批了间隔制）；要做的话是 `nextFireAt` 换成"下次命中的每日时刻"，改动很小但要单独验。
- **非主载体不接唤醒**（裁决 5）；也没有"主载体切换"的专门工具（先用绑定工具的参数，真需要再加）。
- **载体不做移动/寻路**：`registerGoals()` 留空、`setNoAi(true)`，位移只能由核心写速度。它是"载体"，不是"AI 玩家"。
