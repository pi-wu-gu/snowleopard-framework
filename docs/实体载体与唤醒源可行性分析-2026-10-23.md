> 前置：聊天栏通道已实测可达（框架 1.5.1）；聊天工具组设计已冻结（`聊天工具组可行性分析-2026-10-23.md`）。

## 零、前提修正：本项目**独立**，不接星期五

这条不是补充说明，是**改前提**——之前两份文档里"真正的执行端在星期五那一层"的措辞必须作废。受影响三处：

| 原表述 | 修正后 |
|---|---|
| 注入/唤醒的执行端 = 星期五 | 执行端 = **接入方（任意 LLM 宿主）**，本项目只出事件与契约；**没有接入方时请求停在 pending 并可查，绝不假装执行** |
| "宿主（星期五那一层）调用 pull/ack" | "接入方调用 pull/ack"，接口与本项目无关，谁接入谁负责 |
| 唤醒 = 模型→模型 请求 | 唤醒有**三个外部触发源**（玩家互动 / 时钟 / 聊天提及），模型→模型只是其中之一 |

**独立性的实际含义**：本项目提供「事件源 + 工具 + 持久化」，LLM 在哪跑、怎么跑不在本项目职责内。
所以下面所有"唤醒"都只到 **`WakeRequest` 落盘 + 可查** 为止。

## 一、结论

| 需求 | 判定 | 关键结论 |
|---|---|---|
| 创建新实体（载体），复用原版模型，无原版 AI | **可行** | 注册 `EntityType` + `EntityAttributeCreationEvent` + 客户端复用 `HumanoidModel`/原版贴图；`registerGoals()` 留空、`setNoAi(true)`，位移由核心写速度（与现有 Mover 同一条路） |
| 绑定后可被实体互动唤醒 | 可行 | `PlayerInteractEvent.EntityInteract`（右键）+ `LivingIncomingDamageEvent`（被打）；需**每实体冷却**，否则玩家连点=每秒一次唤醒 |
| 可定时唤醒 | **可行，但不能挂实体 tick** | 区块卸载后实体不 tick → 定时会**静默失效**。必须服务器级调度器 + 独立持久化（§3.2，本段最大的坑） |
| 相关信息绑定实体 | 可行（要定权威） | 实体 NBT 存绑定，**但调度信息必须以盘上调度表为权威**（未加载的实体查不到 NBT）；启动时比对，冲突以调度表为准并 WARN |
| 发送消息附带 ID，有名称则用名称 | 可行 | 身份取自实体：`[雪豹·<名称>]`；无名称退化为 `[雪豹·<模型ID>]`；名称冲突时补短 ID |
| 被提到名称时唤醒一次，**ID 不唤醒** | 可行 | 名称匹配用**子串**（中文无词边界），但要求名称长度 ≥2；**只玩家来源的消息触发**（模型自己说的话提到自己会引发风暴） |

**一句话总结**：三条唤醒源本身都不难，难的是三件"看起来能跑、出事才发现"的事——
**定时不能挂实体 tick**、**绑定/调度必须定唯一权威**、**提及唤醒必须排除模型来源**。

## 二、新实体（载体）

### 2.1 注册面（三处，缺一就崩或看不见）

| 面 | 做什么 | 备注 |
|---|---|---|
| `DeferredRegister<EntityType<?>>`（注册表 `Registries.ENTITY_TYPE`，id `snowleopard:avatar`） | 声明实体类型：尺寸 0.6×1.8、`clientTrackingRange` 适当、`fireImmune` 视裁决 | 注册需 **mod 事件总线**（`ModContainer#getEventBus()`），不能挂 `NeoForge.EVENT_BUS` |
| `EntityAttributeCreationEvent`（mod 总线） | `put(AVATAR, Mob.createMobAttributes().add(MAX_HEALTH,20).add(MOVEMENT_SPEED,0.25).add(...))` | 缺这条 → 生成即 `NoSuchElementException` |
| `EntityRenderersEvent.RegisterRenderers`（**仅客户端**，`Dist.CLIENT`） | 复用原版 `HumanoidModel`/`PlayerModel` + 原版贴图（如 `textures/entity/player/wide/steve.png`） | 服务端不加载渲染类；用 `@EventBusSubscriber(value = Dist.CLIENT)` 隔离 |

**"复用原版模型/材质"的边界**：复用**模型类与贴图**，不复用原版实体类（用户明确"创建新的实体"）。
这样客户端零新资源即可显示，后续要换专属外观只改 renderer 一行。

### 2.2 无原版 AI 的三条陷阱

1. **`Mob.checkDespawn` 会远距静默 `discard()`**（本项目已踩过）：绑定载体一旦被丢掉，绑定关系就没了，
   而且**不发死亡事件、不报错**。必须 `setPersistenceRequired(true)`（或 override `removeWhenFarAway`）。
2. **`setNoAi(true)` 是否连带关掉 `travel`（物理）需要实测**：如果关了，位移完全由核心写速度——这正好和
   现有 Mover 的路子一致（Mover 唯一底层就是引擎物理），但要确认"没有 AI 时重力/碰撞仍在"。
3. **死亡 vs 卸载必须区分**：死亡 → 解绑并记原因；区块卸载/世界保存 → **不算解绑**。
   混在一起会出现"实体还在但模型以为它死了"的幽灵绑定。

### 2.3 绑定信息存哪 —— 必须定唯一权威

「相关信息绑定实体」的正确实现不是"只存实体 NBT"，因为**调度器要处理未加载的实体**（§3.2）：

| 数据 | 权威位置 | 理由 |
|---|---|---|
| 绑定的模型 ID | 实体 NBT（`snowleopard:model_id`） | 跟着实体走，实体在哪绑定就在哪 |
| 显示名称 | 实体 NBT（优先用原版 `CustomName`，不另造一套） | 复用原版命名牌机制，玩家能用命名牌改名 |
| 定时策略 + `nextFireAt` | **盘上调度表**（`<storage>/wake-schedule.json`） | 未加载的实体读不到 NBT，但定时仍需按时判断 |
| 实体 UUID ↔ 模型 ID 反查 | 调度表内一并记 | 避免"扫全服实体"这种必然不完整的枚举 |

**冲突裁决**：加载时（`EntityJoinLevelEvent`）比对 NBT 与调度表，不一致**以调度表为准**修正 NBT 并 `WARN`。
理由：调度表能覆盖未加载场景，NBT 不能；两个都"看起来对"时，选覆盖面大的那个，并把漂移暴露出来。

## 三、三类唤醒源

### 3.1 互动唤醒（右键 / 被打）

```
PlayerInteractEvent.EntityInteract  → 右键载体（交互手、手持物、玩家）
LivingIncomingDamageEvent           → 载体被攻击（伤害来源、伤害量）
```

两者都转成 `WakeRequest`：`prompt` 写清"谁、用什么、在哪"，`reason` 写 `interact:right_click` / `interact:attacked`。

- **每实体冷却 10 秒**（玩家连点右键/连续挥砍 = 每秒一次唤醒，不加冷却会被刷）。
- 一次"交互窗口"内只唤醒一次：冷却期内重复互动**不新建请求**，只把计数记进已有请求的 outcome（可选）。
- **被打要不要唤醒**：被攻击也是信息（"有人打我"），但刷怪塔/自动伤害会变成骚扰源。**建议默认开启但可关**
  （配置项），列为待裁决。

### 3.2 定时唤醒（本段最大的坑）

**不能挂实体 tick**。`Mob.tick` 只在实体所在区块加载时执行；玩家走远、区块卸载 → 实体不 tick → 定时静默失效。
而且这种失效**没有任何报错**，只表现为"说好每 10 分钟唤醒一次，玩家离开后就再也不唤醒了"。

正确做法：

```
服务器级调度器（ServerTickEvent.Post 每 20 tick = 1 秒扫一次，只看最小堆顶）
  ├─ 状态：<storage>/wake-schedule.json（entityUuid, modelId, intervalSec, nextFireAt, enabled, lastResult）
  ├─ 到点 → 查实体是否加载
  │    ├─ 已加载 → 发 WakeRequest，nextFireAt += interval
  │    └─ 未加载 → **skipped 记原因**，nextFireAt += interval（不堆积、不补发）
  └─ 防止"补偿风暴"：绝不做 "错过 N 次就补 N 条"
```

- **时间基**：用**现实时间**（epoch 毫秒），不用游戏时间——游戏内时间会被 `/time set`、睡觉、服务器暂停打乱。
- **未加载时跳过而非补发**：唤醒的目的是"让模型在场景里干活"，实体不在场景里唤醒了也没法干；
  补发会在玩家回来那一刻炸出一串请求。跳过并记 `skipped:not_loaded` 是诚实降级。
- **最小间隔**：定时唤醒最短 60 秒（再短就是轮询，等于没有意义地烧 LLM 预算）。
- 存档迁移：`nextFireAt` 存绝对时间，服务器停机跨天也不会漏。

### 3.3 名称提及唤醒（ID 不唤醒）

订阅与聊天记录**同一个 `ServerChatEvent`**（所以本功能依赖聊天工具组的记录能力，顺序在 M13 而非 M12）。

规则：

| 规则 | 取值 | 理由 |
|---|---|---|
| 匹配对象 | 实体**显示名称**（`CustomName` 优先，其次默认名） | 用户明确 |
| **不匹配** ID | 模型 ID / UUID 都不作为唤醒关键词 | 用户明确"ID 不唤醒"；ID 是内部标识，不该成为外部遥控器 |
| 匹配方式 | **子串**，大小写不敏感；名称长度 **< 2 字符禁止作为可唤醒名** | 中文无词边界，"雪" 会在"下雪了"里误触 |
| 触发来源 | **只玩家来源**（`PLAYER`） | 模型 `chat_send` 里提到自己名字会立刻自触发 → 无限风暴（与 chat 注入只认 PLAYER 同一条规则） |
| 一条消息多次提及 | **只唤醒一次** | 用户明确"唤醒一次" |
| 多实体同名 | 全部唤醒，**回执里列出实际命中的实体**；同时**创建时禁止重名**（载体层校验） | 群组里"同名全收到"是有意设计；实体唤醒里重名会让"谁被唤醒了"无法回答 |
| 冷却 | 每实体 10 秒（与互动共用冷却窗口） | 玩家连续刷同一句会变遥控器 |

## 四、消息身份：名称优先，ID 兜底

```
有 CustomName  →  [雪豹·小白]        （玩家能看懂、能用命名牌改）
无 CustomName  →  [雪豹·selftest-m11]（退化为模型 ID，保持可追溯）
名称冲突       →  [雪豹·小白(m11)]    （短 ID 只在冲突时补，不污染常态）
```

三处都要用同一套身份解析（**只有一处实现**，别各写一份）：
① `chat_send` 的前缀 ② `ChatPush` 摘要里的归属 ③ 提及唤醒的回执。
> 这是"同一职责多实现必漂移"的直接应用：三处各拼一次名字，改一处就漂。

**"附带 ID"怎么理解**：用户要求"发送消息时附带 ID，如果有名称则使用实体名称"——两者不是并列，而是**先后**：
有名称用名称、没名称才用 ID。但为了让**追溯**不丢，建议 `chat` 记录里始终写完整 `modelId`（落盘字段），
只有**展示前缀**走"名称优先"。这样玩家看到的是名字，模型和日志看到的是 ID。

## 五、职责切分（修正版，无星期五）

| 层 | 负责 | 不负责 |
|---|---|---|
| **core** | `WakeStore` 六道闸、配额、幂等、`pending/complete` | 任何 MC 概念 |
| **壳（本仓）** | 载体实体、三类事件源、调度器、绑定/调度持久化、`chat` 记录与注入块 | 执行唤醒（没有 LLM） |
| **接入方**（本项目外，任意宿主） | 取 `pending()` → 跑模型 → `complete()`；`chat` 的 `pull/ack` | 绑定与调度判定（都由壳给） |

**外部触发的 `from` 约定**（重要）：玩家/时钟/提及都不是模型 ID，所以 `from` 用**带前缀的伪 ID**：

```
player:muyiyang      ← 玩家互动
clock                ← 定时
mention:muyiyang     ← 提及唤醒
```

绝不能借用某个真实模型 ID 当 `from`——那会让核心的"自唤起/成环/黑名单"判定全部失真。
同时：**黑名单只管模型 ID**（"我不接受谁唤起我"防的是模型互相骚扰），玩家触发不受黑名单限制。

## 六、风险表

| # | 风险 | 处置 |
|---|---|---|
| 1 | 定时唤醒挂实体 tick → 玩家走远后静默失效 | 服务器级调度器 + 盘上 `nextFireAt`（§3.2） |
| 2 | 实体被 `checkDespawn` 静默 discard → 绑定凭空消失 | `setPersistenceRequired(true)`；死亡与卸载分开处理 |
| 3 | 绑定/调度双写漂移 | 调度表为权威，加载时比对并 WARN（§2.3） |
| 4 | 玩家连点右键/连击 → 唤醒风暴 | 每实体 10 秒冷却（三源共用） |
| 5 | 模型提到自己名字 → 自触发风暴 | 提及只认 `PLAYER` 来源 |
| 6 | 重名 → "谁被唤醒"无法回答 | 创建时禁止重名 + 回执列实际命中 |
| 7 | 短名误触（"雪"） | 名称长度 ≥2 才允许作为唤醒词 |
| 8 | 未加载实体补发堆积 | 跳过并记 `skipped:not_loaded`，不补发 |
| 9 | 新实体与现有实体组抢控制权 | 载体只受核心写速度；`sense`/`entity` 组对它照常可用（它就是个实体） |
| 10 | 复用原版模型导致客户端渲染崩 | renderer 只在 `Dist.CLIENT` 注册；服务端类不触碰客户端类 |

## 七、验收断言草案（AvatarCheck + WakeSourceCheck，约 24 条）

```
① 载体（7）：注册成功且可取到 EntityType / 属性齐全（生成不抛） / 无 goal（getGoals 为空或 isNoAi）
   远距不 discard（造 200 格外仍存在）/ 死亡 → 解绑且有原因 / 卸载 → 不算解绑 / NBT 存 model_id
② 互动唤醒（5）：右键 → 一条 pending / 冷却内连点 → 仍只一条 / 被打 → pending（可配关闭后 → 无）
   prompt 含玩家名与坐标 / 冷却过后再点 → 新一条
③ 定时唤醒（5）：到点产生 pending / interval 正确推进 / **实体未加载 → skipped 且不堆积**
   最小间隔 60 秒下限（传更小 → 拒绝或抬到 60）/ 服务器重启后 nextFireAt 不丢
④ 提及唤醒（4）：名称命中 → 一条 / 同一句提两次 → 仍一条 / **模型来源消息提及 → 不触发**
   ID 提及 → 不触发
⑤ 身份（3）：有名称 → 前缀是名称 / 无名称 → 前缀是 ID / 重名创建 → 拒绝
⑥ 权威（3）：改 NBT 与调度表不一致 → 加载时以调度表为准 + WARN / 调度表缺失 → 从 NBT 重建 / 双向都有 → 不重复绑定
```

## 九、待裁决（括号是我的推荐）

1. **被打是否唤醒**：默认开、可由配置关（推荐）／始终算互动／永不算。
2. **定时粒度**：只做"每 N 秒间隔"（推荐，简单确定）／还要"每天固定时刻"／还要"游戏内时间"（不推荐，会被 `/time set` 打乱）。
3. **未加载时**：跳过并记原因（推荐）／仍发 pending 但标"实体未加载"／等实体加载后补发（不推荐，会堆积）。
4. **重名**：创建时禁止（推荐）／允许，回执里列全部命中。
5. **一个模型能否绑多个载体**：允许多个但只有一个"主载体"接收唤醒（推荐）／严格 1:1／完全允许多个各自独立唤醒。
6. **复用哪个原版模型**：`HumanoidModel` + `steve.png`（推荐，最中性）／`VillagerModel`／`ZombieModel`。
