> "先澄清'UI'对实体意味着什么，再判合成栏怎么做"展开。

## 一、先澄清："UI 交互"对载体意味着什么

载体是一个**实体，没有屏幕**。"UI 交互"可能的四种解读：

| 解读 | 判定 |
|---|---|
| ① 与方块容器界面交互（箱子/木桶 GUI） | **已覆盖**——服务端直接读 Container（`container_items` / `move_item` 按 `x,y,z:槽` 寻址），GUI 只是客户端皮，实体不需要"打开" |
| ② 自身背包/合成栏界面 | 即**合成栏本组**（§二）——玩家的 2×2 随身合成属于背包界面，实体版=服务端等价操作 |
| ③ 有 UI 的特殊方块（告示牌/酿造台/附魔台） | 告示牌=改文字（可加 `sign_edit`，小工具）；酿造台/附魔台=专用 Container 逻辑，**v1 不做**（记账） |
| ④ 给玩家开屏（模型向玩家展示界面） | **明确不做**——需要客户端渲染配合 + 越权风险（模型对玩家弹窗），跨端复杂度与收益完全不成比例 |

**结论**：所谓"UI 交互"组，落地形态是 **`craft`（合成）组**——②是主体，①③已有或顺手，
④明确不做。独立成组而非并入 item：合成的状态（配方发现/材料扣减/产物回填）与"搬东西"是两种职责。

## 二、自身合成栏：两条路线

### 路线 A：配方直合成（**推荐 v1**）

```
craft_recipes(keyword?, limit)   # 发现：列可用配方（输出名/材料清单/是否需要工作台）
craft(recipe_id, count=1)        # 执行：从 self:pack 扣料 → 产物回填 self:pack（满则报错列占用）
```

- **服务端实现**：`RecipeManager.byKey(recipeId)` → `CraftingRecipe.assemble(...)`；
  材料从九格背包逐槽扣（`CraftingInput` 装配 + 校验）；产物 `RemainingItem`（桶/碗退回）一并处理。
  纯服务端，无任何 UI/客户端参与——**可行**。
- 优点：无网格状态、无半成品退料、无"网格内容持久化"问题；LLM 只需要配方 ID。
- 缺点：模型要先查配方（`craft_recipes` 解决——按输出名/材料名 keyword 过滤，返回材料清单）。

### 路线 B：网格合成（还原玩家 UI 操作）

`craft_fill(grid)`（3×3 从背包取料摆格）/ `craft_take()` / `craft_clear()`。

- **判定：v1 不做**。网格是**有状态**的：内容要不要随实体 NBT 持久化？半成品放一半断会话怎么退料？
  三个新状态问题换来的只是"操作过程更像人"——对 LLM 毫无价值（它不需要模仿点按，它要结果）。
  若真要拟真，路线 A 之上加一层"演示网格"即可，随时可补。

### 两个必须裁决的语义

1. **3×3 是否要求工作台邻接**：服务端合成不强制。建议——**不要求**（v1 从简），但 `craft_recipes`
   返回里标注 `needs_table`；后续要拟真再加"4 格内有工作台才放行 3×3 配方"的闸。
2. **材料不足的失败语义**：必须 **Error 并列出缺口清单**（缺 橡木原木×2 等）——不许静默半合成
   （扣了料出不了产物=假成功家族）。

## 三、新增工具清单（craft 组，4 个）

| 工具 | 语义 | 权限/护栏 |
|---|---|---|
| `craft_recipes(keyword?, limit=20)` | 列可用配方（id/输出/材料/needs_table） | 只读 |
| `craft(recipe_id, count=1)` | 直合成：扣 pack 料 → 产物（含 RemainingItem）回 pack | count ≤ 8；pack 满则 Error |
| `craft_grid_view()` | v2 预留（路线 B） | 不实现 |
| ——（并入） | `sign_edit(pos, lines)` 顺手项（告示牌，③类） | 可选，另议 |

## 四、风险与防线

| # | 风险 | 防线 |
|---|---|---|
| 1 | 配方 ID 海量（上千） | `craft_recipes` 只按 keyword 分页返回；模型先查再合 |
| 2 | 材料扣一半失败 | 先校验全部材料够 → 再统一扣；产物先造 → 回填失败则全量退料（事务性） |
| 3 | 产物塞不下背包 | 回填前查空位；不够 → Error 列"需要 N 空位"，不丢产物 |
| 4 | RemainingItem（桶/碗）遗漏 | assemble 后按 recipe 的 getRemainingItems 补退 |
| 5 | 数据包配方与原版差异 | 统一走 RecipeManager，数据包配方天然可用 |
