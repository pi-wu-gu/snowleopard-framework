## 〇、总则

1. **里程碑顺序即依赖**：M1（绑定+感官+自我状态）是其余组的地基，不许并行超前；
2. **两层测试**：纯逻辑（状态机/环形缓冲/双索引/参数校验）拆出 MC 依赖 → JUnit headless（`./gradlew test`，秒级）；
   MC 面（实体/方块/容器）→ 模组内真机自测（参照 Friday 证据链：造场景→断言→同版本重跑定抖动）；
3. **假成功比失败更坏**（Friday 铁律）：工具失败必须 `Result.error` 或抛异常，禁止失败文本进 Ok；
   动作完成以**服务端回推**判定，不信用客户端本地状态；
4. **危险动作先标注后功能**：`reversible/state` 进工具清单接核心权限门禁，与功能同 M 落地不后补；
5. **两模块纪律**：`shell`（装配/SPI/报告）保持零工具逻辑；`entitytools` 只做 MC 能力面，
   不写 agent-loop/记忆（决策在 core）。

## 一、里程碑（每步可独立验收、独立发布）

| 项 | 内容 | 验收 |

### M1 绑定 + 感官 + 自我状态（地基，最大语义件）

| 项 | 内容 | 验收（真机） |
|---|---|---|
| 感官开关 | `sense.open/close/status`：open→等待选取；close→**控制类工具显式禁用**（报"感官未开启"） | 未开启调用任一控制工具被拒且原因可见 |
| 候选三件套 | 选取期间向模型提供：实体信息 / 位置信息 / 周围环境信息 | 信息完整可读、含候选编号 |
| 选取绑定 | `entity.pick` → **1:1 绑定**；未选取候选**全部休眠**（冻结活动、查询标注 `dormant`） | 选中者可查、未选者休眠不响应交互 |
| 死亡流 | **实体死亡→感官自动关闭**（不自动重绑；重开走选取） | 杀死后控制工具自动禁用 |
| 反查 | `entity.status` 双向（model→entity / entity→model） | 双向一致 |
| 自我观测 | `entity.self_status`：位置/朝向/血/饥饿/状态效果/装备/维度/水/火 | 全字段可信（与 F3 面板对账） |

> 微项（本 M 顺手定）：已绑定再开感官是否提示二次确认（挂核心 `confirm_token` 即可）。

### M2 视角

| 项 | 内容 | 验收（真机） |
|---|---|---|
| 朝向 | `look(yaw,pitch)` + `look_status` 查询（单位=度） | 设定与查询一致 |
| 锁定 | `look_at(方块\|实体, 面\|中心, 时长)` + `unlock` | 方块面命中指定面；实体锁定在中心 |
| 六结束路径 | 显式解锁/方块消失/实体消失/超距 64/超时/被外力夺控——**每条上报原因** | 六条各触发一次，原因逐一核对（FridayLock 同款断言） |
| facing 组件 | 交互共用的朝向组件先立接口（M3 复用） | 组件有独立单测 |

### M3 交互

| 项 | 内容 | 验收（真机） |
|---|---|---|
| 四动作 | `attack/use/place/break`；显式目标（坐标/实体 id）优先、缺省准星 | 四动作各成功一次 |
| 完成判定 | **服务端回推**：破坏=方块更新推回；攻击=伤害事件/血量变化；放置=方块出现 | 断言读服务端事实（S8 同款） |
| 持续动作 | 破坏带挖掘时长/进度（硬方块） | 硬方块完整挖完、超时报因 |
| 寻址红线 | 目标为**其他编号实体一律拒绝**（裁决） | 攻击他人实体被拒且说明 |
| 危险标注 | 四动作 `reversible/state` 进清单；攻击真人默认走审批 | 权限文件关掉即拒、审批链可见 |

### M4 移动（最大工程件）

| 项 | 内容 | 验收（真机） |
|---|---|---|
| 基础移动 | `sneak(开\|关)` / `jump` / `move(方向, 时长\|距离)`——**三驱动并存**（裁决） | 三驱动各跑通；蹲是独立姿态 |
| goto 寻路 | `goto(坐标)`：A* + 引擎物理滑动（**禁 setpos**） | 到达判定 **DONE=连续 2 tick 贴住目标** |
| 阻塞判定 | 单 tick **水平**位移 <0.02 连续 12 tick = 阻塞（3D 会把垂直漂移误判成进展） | 卡墙场景上报阻塞而非假成功 |
| 不可达语义 | 水中/悬崖/高差>阈值 → 显式失败原因；路径重算；超时 | 三种不可达各报因 |
| 控制面 | `stop`（中断）/ `move_status`（位置/速度/进行中） | stop 即停、status 反映真实 |

### M5 物品 + 世界

| 项 | 内容 | 验收 |
|---|---|---|
| 自身物品 | `item.self_items`（含装备栏）：**双索引检索**（registry name + 显示名），显示按语言 | 中英检索各命中同一件 |
| 容器 | `item.container_items`：容器寻址（准星/坐标/自身背包 三选一） | 三种寻址各命中 |
| 物品移动 | `item.move_item`（数量拆分/整组）/ `item.drop`——**容器 slot API，不走 GUI** | 拆分数量精确、服务端槽位核实 |
| 世界查询 | `world.query`（中心\|框选 + 半径\|两角 + 检索 + 含实体）——单一工具 | 两种形状各命中；含实体带归属标注 |
| 双护栏 | **仅已加载区块声明** + **返回量上限截断带说明**（默认安全、显式放开） | 未加载区声明可见；超量返回带截断标记 |

### M6 动态感知

| 项 | 内容 | 验收 |
|---|---|---|
| 监视控制 | `watch/unwatch/watch_list`（与视角"锁定"分名） | 列表与监视集一致 |
| 动态记录 | `watch_events`：事件驱动 + 轨迹**环形缓冲**；**保留窗口**（时间/条数上限）；轨迹限频 | 窗口外淘汰、上限不涨内存 |
| 归属标注 | 每条动态带 `controller`（绑定实体=模型 ID，真人=空）——含绑定实体与真人（裁决） | 混合场景标注逐一核对 |
| 触发挂点 | 自动记录挂核心 `TriggerRegistry`（坏钩子不杀主链）；动态**不进记忆** | 坏钩子注入不杀整轮 |
| 主动查询 | 查询玩家/绑定实体动态（事件集+轨迹枚举写死） | 枚举与记录对账 |

## 二、契约冻结清单（改=升 coreApi / 显式迁移）

| 契约 | 内容 |
|---|---|
| 工具清单 schema | `tools` 字段形态（name/summary/usage/params）+ `reversible/state` 标注 |
| `sense` 状态机 | 开→等待选取→绑定 / 关→工具禁用 / 死亡→自动关——三态转换表 |
| 绑定模型 | 1:1、休眠语义（dormant）、双向反查键 |
| 三件套信息结构 | 实体信息/位置信息/周围环境信息的字段表（M1 冻结） |
| `controller` 字段 | 动态条目的控制模型编号（真人=空） |
| 数值单位 | tick/秒、度、绝对/相对坐标（全工具统一） |
| 完成判定口径 | 服务端回推；DONE=连续 2 tick；阻塞=水平位移阈值 |

## 三、工程纪律（全部踩过，勿再犯）

- **假成功比失败更坏**：完成判定读服务端事实；客户端本地状态不可信（S8 教训）。
- **阻塞判定用水平位移**：3D 位移会把垂直漂移误判成有进展（Friday Mover 教训）。
- **仅已加载区块**：`getBlockState` 返空气不报错——查询必带声明（Friday 教训）。
- **六条结束路径全部上报原因**（FridayLock 教训）；少一条就是静默失效。
- **多控件/多实体断言按 id 取**，取"第一个"必假失败。
- **真机断言依赖机器负载+世界地形**：同版本重跑即过才能定抖动；拿不出证据当产品问题查。
- **改输出格式全仓 grep 旧断言**；改异常类型全仓 grep 捕获点。
- **工具失败必须抛异常或 Result.error**，绝不返回 "[failed]" 文本（会被包成 Ok）。
- 中文不进标识符；记录一律带时间戳；文档追加后从头校对（防自相矛盾）。

## v1.12.3 —— 瞳孔"跑到下颚中间"真因：动画覆盖了 PartPose 基准位移（2026-10-27 04:55 (UTC+8)）

用户真机截图为证：**黑色瞳孔出现在下颚正中（头的 pivot 高度）**，眼白位置正常。

根因不在几何、不在 UV、不在坐标转换。生成的 `setupAnim` 里写了：

```java
this.eyePupilLeft.x = gazeX;   // gazeX ≈ ±0.2
this.eyePupilLeft.y = gazeY;
```

而 **`ModelPart.x/y/z` 就是 `PartPose.offset()` 的基准位移本身**（`bake()` 时 `setInitialPose` + `loadPose`
写进这三个字段）。赋成 ±0.2 等于把瞳孔的 `(-2, -4.5, -6.175)` **整个抹掉**，
瞳孔于是落在眼睛组 pivot（= 头的 pivot，bb y 16）——正是"下颚中间"。

修法（3 行）：

```java
this.eyePupilLeft.resetPose();   // 恢复 PartPose 基准（resetPose 源码即 loadPose(initialPose)）
this.eyePupilLeft.x += gazeX;
this.eyePupilLeft.y += gazeY;
```

**铁律（新增，跨模型通用）**：`setupAnim` 里改 `x/y/z` 必须先 `resetPose()` 再 `+=`；
改 `xRot/yRot/zRot` 必须写成 `基准角 + 增量`（本生成器的尾巴/下颚早已如此）。
生成器自检新增一条断言：任何 `this.<part>.x/y/z = ...` 直接赋值即报错退出。

同时记录：**旋转类被覆盖**不会这么明显（尾巴会僵直、耳朵不抖），但**位移类被覆盖会瞬移**，
两者同一病根——"基准姿态与动画增量必须分离"。

## v1.12.7 —— 视觉 P4：真渲染（客户端抓帧）（2026-10-27 12:35 (UTC+8)）

把 `stub` 换成真后端：服务端发包 → 客户端抓一帧 → 回执落盘。

### 做法：换相机 + 抓主缓冲（而不是手搓离屏渲染）

原计划是 `RenderTarget + Camera + renderLevel(DeltaMatrix…)` 自己画一遍。实际实现改成：

1. 收到请求 → `mc.setCameraEntity(载体)`（客户端本地实体，按 entityId 找）；
2. 下一帧 `RenderLevelStageEvent.Stage.AFTER_LEVEL` 时用 `Screenshot.takeScreenshot(mc.getMainRenderTarget())`
   抓主缓冲 → 区域平均降到请求尺寸 → `PngWriter` 编 PNG；
3. **立刻** `setCameraEntity(mc.player)` 还原。

理由：手搓矩阵那套要自己准备 projection/modelview/雾/光照贴图/裁剪，**每次大版本都可能坏**，
而且盲写极易黑屏；换相机能把光照/雾/实体/天气/区块批次全部交给原版。

**代价**：玩家视角会闪**一帧**（≈16ms，肉眼几乎不可见）。这是明确接受的交换：
用一帧闪烁换来零渲染管线维护。

### 硬限制与拒绝路径

**客户端只能渲染自己已加载的区块**。受理阶段就判定：同维度 + 距载体 ≤128 格 + 该区块已加载，
否则**当场报错**并指路 `vision/scan`（服务端射线任何距离都成立）——

> 没有客户端可渲染 比 渲染出空世界 好一万倍：假画面会让模型笃定"前方是空的"。

### 其它要点

- 回执只认**第一个到达**的（`VisionPending.modelOf` 查不到即过期回执，静默丢弃，不覆盖已就绪的图）；
- 超时清扫：`onServerTick` 每 20 tick 扫一次，REQUESTED 超时 → FAILED + 注入失败提示
  （图永远不回来时也必须让模型知道失败，不能一直"稍等"）；
- 包体积：`ClientboundCustomPayloadPacket.MAX_PAYLOAD_SIZE = 1048576`，384×216 真图约 80–200 KB，安全；
- 两侧都注册 payload（否则通道对不上）；客户端实现放在 dist 判断之后再解析，
  专用服务器上不会加载客户端类。

### 真机（30 → 仍 30，但含真图）

P3 的四条断言不变，但这次图是**客户端真实画面**而不是测试桩——
断言里已校验 PNG 签名与存在性，肉眼验收看附件图即可。

## v1.13.2 —— 图像注入留凭据 + 移动带朝向（2026-10-27 17:00 (UTC+8)）

对着旁边，边走边看不到路。现在 `actuate` 每 tick 把 yaw 对准实际速度向量（`atan2(-vx, vz)`），

## v1.14.0 —— 载体转头与瞳孔注视（2026-10-27 19:00 (UTC+8)，内核仍 0.6.1）

命题：载体要能转头、瞳孔能移动，指向"查看类工具看的位置或锁定的生物"，限幅，到上限才轻微移动身体。
追加裁决：控制朝向也先转头；移动时收束至同一方向（除非锁定生物）；转向要平滑防多点切换抽搐；
**瞳孔是平移不是旋转**；截图走"相机跟随视线"。

### 1. 根因：模型早就会转，是上游把差值喂成了 0

`SnowLeopardModel.setupAnim` 一直有 `head.yRot = netHeadYaw`、瞳孔 `±0.2px` 平移；
但 `tickViewLock` 是 `setRotation(self, aim)` **整体转身体** → `netHeadYaw ≡ 0`、瞳孔恒居中。
加上 `AvatarEntity` **一个自定义 SynchedEntityData 都没有**，服务端算出的角度也到不了客户端。
所以本版做的不是"重做动画"，而是补上游 + 补同步通道。

### 2. 新增 `AvatarGaze`（entitytools，纯 Java，14 条单测）

维护两个世界角（`gazeYaw` 视线 / `headWorldYaw` 头），**各自限速**：
`GAZE_SLEW=12` > `HEAD_SLEW=8` → 眼先动、头后追、眼回中，**先后关系由速率涌现**，不写静态分档
（写了反而小角度时头不动、大角度时瞳孔永远居中）。

- 常量：头 ±65°、俯仰 ±35°、瞳孔 ±0.2/±0.15px、身体 6°/tick（俯仰 3）、驻留 10 tick。
- 来源枚举带优先级：`LOCK(3) > MOVE(2) > LOOK(1) > IDLE(0)`；降级要过驻留期，升级可立即抢占。
- 最短弧 `wrap()`：179→-179 只走 2°（否则视觉上猛抽一整圈）。
- 身体只在头到限位后才动（6°/tick）；**移动时身体归行进方向，视线不抢**。

### 3. 同步通道

`GazeCarrier` 接口（entitytools）+ `AvatarEntity` 4 个同步数据浮点
（头像对 yaw/pitch、瞳孔像素 x/y）。变化阈值 0.5°/0.02px，避免每 tick 发四个包。
只同步**最终值**，不同步世界角——客户端不复算映射，两边不会漂移。

### 4. 朝向统一出口：`tickViewLock`

原三处各写 `setRotation`（锁定 / 移动 / look）会互相抢写 → 头在方向间跳。现在只有
`tickViewLock` 写朝向，其余入口只声明"我想要哪个来源"。身体权威：**移动 > 凝视**。

- `look()` 改为设**持续目标**（TTL 600 tick），回执如实说"眼先动、头随后、约 N tick 到位"。
- `actuate` 不再写朝向；`faceMovement` 及其 `if (locked) return` 删除（否则 goto 侧着滑）。
- `unlock` / `unbind` 复位视线（否则"卡住脸"）。
- **漂移判据改为比"实际写入值"**：渐进期间身体每 tick 都不到目标，若拿 aim 比，
  下一 tick 就被判"外力夺控"而解锁——不报错的死法。

### 5. 客户端渲染

`setupAnim` 读同步值 + `Mth.rotLerp(0.4)` 插值；`head.resetPose()` 后再 `+=`；
瞳孔改 `ModelPart.x/.y` **平移**（1×1×1 方块绕自身转几度视觉上等于没动）。

### 6. 截图与扫描同一口径

`PovCapture` 抓帧前把身体角临时补成"身体+头"（抓完立刻还原）；`VisionScan` 用合成视线向量。
否则会出现"扫描说前方空地、照片里是墙"。

**验收**：`./gradlew build` 96 项测试全绿（新增 14 条 AvatarGaze）；真机待跑。
