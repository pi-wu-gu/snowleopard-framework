# 客户端验收通道（真 GUI）

> 2026-10-23 23:05 (UTC+8) · 对象：雪豹框架壳 · 目标：用**真实客户端**验证聊天栏推送
> 结论先行：**通道已就绪，但本轮没能在这台机器上自动跑完**——拦路的是环境（见 §三），不是代码。

## 一、两条通道

| 通道 | 开关 | 做什么 |
|---|---|---|
| **客户端验收模式** | 服务器 `-Dsnowleopard.clienttest=true`（gradle `-PclientTest`） | 跳过全量自测（不建 8 座塔、不 `halt`），等真人进服后跑：造僵尸猪灵 → 绑定 → 造一条群未读 → `TurnSummary` → `ChatPush.push` |
| **客户端自连** | 客户端 `-Dsnowleopard.autoconnect=host:port`（gradle `-PquickPlayMp=host:port`） | 标题界面（且加载覆盖层撤掉）后自动连服务器 |

为什么要有第一条：`SelfTestScenario` 收尾会 `server.halt(false)`，在集成服务器上等于把客户端关掉。

## 二、自助跑法（人在机器前时最快）

```bash
# 终端 A：服务器（验收模式，等真人连）
cd shell && ./gradlew runServer -PclientTest

# 终端 B：dev 客户端（自动连上去）
cd shell && ./gradlew runClient -PquickPlayMp=localhost:25565
```

进服约 3 秒后，游戏内聊天栏应出现两行：

```
[雪豹] 提醒：群组未读 g00001(1) · 新消息 1 条
[雪豹] 客户端验收完成：绑定 3f2a91c8… · 聊天栏推送已接通
```

日志侧对应 `[雪豹框架][CLIENT] PASS: 聊天栏推送送达（真客户端可达） | sent=true`——
这句是专用服务器**做不到**的断言（那边 `push` 只能返回 false 落日志）。

## 三、本轮踩到的环境限制（都不属于代码问题）

| # | 现象 | 证据 |
|---|---|---|
| 1 | **dev 客户端里 `--quickPlaySingleplayer / --quickPlayMultiplayer` 完全不生效** | 两次启动（单人 sltest / 多人 localhost）主日志都没有任何 quickplay 记录；加 `--quickPlayPath` 后该文件根本没被创建 |
| 2 | 客户端停在**加载覆盖层** | 日志停在 `Loaded 0 entity animations`，之后无任何输出；`mc.getOverlay() != null` 的守卫使自连逻辑一直不发起（这正是"覆盖层没撤就连接会被吞"的同一现象） |
| 3 | 沙箱**禁止 GUI 自动化** | `Add-Type`（编 .NET）与 `New-Object -ComObject WScript.Shell` 均被安全策略拦截 → 无法把窗口提到前台、无法点"多人游戏→直接连接" |
| 4 | 截屏只能抓到**另一个** MC 实例 | 桌面截屏（Java Robot 可用）显示的是用户自己那个带小地图的客户端，dev 客户端窗口在它后面且无法聚焦 |

## 五、下次要验时先做这一步

启动后先确认**加载覆盖层已撤**（聊天栏可见、FPS 显示正常），再谈连接；或者干脆放弃键盘鼠标自动化，
直接用 §二 的两条命令由人确认。**不要**再去试 quickPlay 参数——本版本 dev 客户端已实测无效，别再花时间。

## 六、2026-10-24 00:10 (UTC+8)：**根因找到了，自动化通道打通**

前面 §三、§五 的结论（"客户端验收在本机不可自动化"）**是错的**，作废。真实原因只有一个：

> **首次运行的"辅助功能引导屏"挡住了标题界面。**
> 就是那道 `Welcome to Minecraft · Narrator: OFF · Continue / Accessibility Settings` 的屏。
> 它不是 `TitleScreen`，quickPlay 与任何"等标题界面再连接"的逻辑都不会触发——
> 表现就是"客户端起来了、日志停在 `Loaded 0 entity animations`、永远不进服"，
> 而 `jstack` 显示 Render thread 正常在 `RenderSystem.limitDisplayFPS` 里等帧，**根本没有卡死**。
> 之前两次判断成"加载覆盖层没撤 / quickPlay 无效"，都是被这个现象误导。

**解法**：版本目录的 `options.txt` 里必须有 `onboardAccessibility:false`（点一次 Continue 就会写进去；
也可以从任何已经跑过的版本复制一份）。加上之后：

| 步骤 | 结果 |
|---|---|
| `python tools/launch-real-client.py --root <MC根> --version 雪豹测试 --join --wait` | 客户端启动 → 标题界面 → 自动连 `localhost:25565` |
| 服务器 `runServer -PclientTest` | 收到真人进服，3 秒后跑 `ClientSmokeTest` |
| 实测（2026-10-24 00:00，玩家 `SnowTester`） | **6 PASS / 0 FAIL**，含 `聊天栏推送送达（真客户端可达）| sent=true` |

这一轮走的是**真实客户端 + 真实 jarJar 内嵌 + 真实资源**（不是 dev 客户端），
日志确认 `core_api=1 · 核心版本 0.5.1 · 工具组 15 个（builtin 6 + mod 9）· SELFTEST PASS`。

### 顺带发现并修掉的两个真 bug

1. **`gradle.properties` 里的中文 displayName 是乱码**（`éªè±¹æ¡æ¶`）
   根因：Java `Properties` 规范按 **ISO-8859-1** 读取，UTF-8 中文被读坏一次，再写进 `neoforge.mods.toml`。
   修法：`mod_name=\u96ea\u8c79\u6846\u67b6 (Snow Leopard Framework)`——转义后才是正确的 Unicode。
   这个 bug 只在"从零装 jar 看模组列表"时才暴露，dev 环境看不出来。
2. **PCL2 的扁平化版本 JSON 里同一条库出现两次**（gson / guava / commons-lang3），
   `BootstrapLauncher` 按路径建映射 → `IllegalStateException: Duplicate key`，客户端起不来。
   修法：脚本里对 classpath 去重（启动器自己做，手搓命令行的必须自己处理）。

### 还有一个沙箱坑（不是游戏问题）

父进程一退出，子进程会被一起回收——表现为"日志 0 行、进程瞬间消失"。
所以脚本必须 `--wait` 守着进程，或在后台任务里跑。

### 音效/显示旁注

`stdout` 在 Windows 管道里默认不是 UTF-8，中文日志会变乱码；但**游戏自己写的
`versions/<ver>/logs/latest.log` 是正常的 UTF-8**（排查要看那份，不要看我重定向的 stdout）。
脚本已加 `-Dstdout.encoding=UTF-8` 缓解。
